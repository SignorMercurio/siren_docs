端口转发在服务端上打开一个 TCP 端口，把流量经目标客户端转发到它能访问的服务，例如仅监听 `localhost` 的管理后台或内网数据库。只能通过 [服务端 REPL](/reference/repl) 的 `fwd` / `lsfwd` / `stopfwd` 操作，Web 控制台没有入口。

<Callout title="监听范围" type="warn">
  转发端口开在服务端主机上并监听所有网络接口。服务端暴露在公网或共享网络时，用安全组、防火墙或仅本机访问限制来源，不要把敏感服务的转发端口暴露给不可信网络。
</Callout>

## 开始转发

```bash title="siren_server"
>>> fwd <Client ID> <转发规则>
```

| 转发规则 | 目标地址 | 示例 |
| --- | --- | --- |
| `<serverPort>:<clientPort>` | 客户端侧 `localhost:<clientPort>` | `fwd 0 8080:8000` |
| `<serverPort>:<targetHost>:<targetPort>` | 从客户端可达的指定主机和端口，例如内网主机 | `fwd 0 8080:192.168.1.10:3306` |

端口范围 `1–65535`，同一服务端源端口同时只能用于一条转发。之后访问 `http://<服务端 IP>:8080`（与服务端同机时用 `localhost`）。客户端连不上目标主机和端口时，转发也无法访问目标服务。

## 查看与停止

```bash title="siren_server"
>>> lsfwd
>>> stopfwd <Forward ID>
```

`lsfwd` 列出每条转发的 `Forward ID`、`Client ID` 和形如 `8080 -> localhost:8000` 的描述。客户端断线或服务端重启后，需要重新打开转发。

## 常见排查

- 源端口无法监听：端口是否被其他进程或已有转发占用，以及是否有权限监听。
- 访问源端口无响应：客户端是否在线，目标服务是否在监听，目标主机能否访问目标地址。
- 其他机器无法访问转发端口：服务端的防火墙、安全组或本机网络策略是否允许该来源。
