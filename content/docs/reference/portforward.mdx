端口转发在服务端上打开一个 TCP 端口，把流量转发到目标客户端可访问的服务。它常用于访问只在目标主机本机或内网开放的服务，例如：

- 仅监听 `localhost` 的 Web 管理后台
- 目标主机内网中的数据库
- 目标主机上运行的其他内网服务

<Callout title="仅 REPL 支持" type="info">
  端口转发只能通过 [服务端 REPL](/reference/repl) 的 `fwd` / `lsfwd` / `stopfwd` 命令操作，Web 控制台没有等价入口。
</Callout>

## 转发方向

```mermaid
graph LR
    A[操作者浏览器或客户端] -->|访问 服务端:8080| B[服务端<br/>监听源端口]
    B -->|SIREN 连接| C[SIREN Client<br/>目标主机]
    C -->|TCP 连接| D[目标服务<br/>localhost:8000]
```

访问路径是：

1. 操作者连接服务端的源端口。
2. 服务端通过已连接的客户端转发数据。
3. 客户端从目标主机侧连接目标地址和端口。

<Callout title="监听范围" type="warn">
  转发端口开在服务端主机上，并监听所有网络接口。若服务端暴露在公网或共享网络中，请用安全组、防火墙或只从本机访问的方式限制来源，不要把敏感服务的转发端口暴露给不可信网络。
</Callout>

## 命令格式

`fwd` 的第二个参数有两种写法：

| 格式 | 目标地址 | 示例 |
| --- | --- | --- |
| `<serverPort>:<clientPort>` | 客户端侧 `localhost:<clientPort>` | `8080:8000` |
| `<serverPort>:<targetHost>:<targetPort>` | 客户端可访问的指定主机和端口 | `8080:192.168.1.10:3306` |

端口范围是 `1–65535`。同一个服务端源端口同一时间只能用于一条端口转发。

## 开始转发

假设目标服务运行在目标主机的 `localhost:8000`，期望通过服务端的 `8080` 端口访问：

```bash title="siren_server"
>>> fwd 0 8080:8000
```

启动后，如果浏览器和服务端在同一台机器上，访问 `http://localhost:8080`；否则访问 `http://<服务端 IP>:8080`，并确认服务端网络策略允许该来源连接。

## 转发到客户端内网

目标地址从客户端一侧发起连接，因此可以填写客户端所在内网中可达的主机。

```bash title="siren_server"
>>> fwd 0 8080:192.168.1.10:3306
```

<Callout title="转发到其他主机" type="info">
  `targetHost` 是从目标主机看出去的地址。如果客户端不能连接该主机和端口，端口转发也无法访问目标服务。
</Callout>

## 查看端口转发

```bash title="siren_server"
>>> lsfwd
```

输出列出 `Forward ID`、`Client ID` 和形如 `8080 -> localhost:8000` 的转发描述。

## 停止端口转发

```bash title="siren_server"
>>> stopfwd <Forward ID>
```

`Forward ID` 来自 `lsfwd` 输出，取值范围 `0–255`。停止转发会关闭服务端上对应的监听端口；客户端断线或服务端重启后，活动端口转发也需要重新打开。

## 常见排查

- 源端口无法监听：确认该端口未被其他进程或已有转发占用，并检查是否有权限监听该端口。
- 访问源端口无响应：确认客户端仍在线，目标服务正在监听，且目标主机能访问目标地址。
- 其他机器无法访问转发端口：确认服务端的防火墙、安全组或本机网络策略允许对应来源连接。
