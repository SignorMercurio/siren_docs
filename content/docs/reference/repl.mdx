服务端 REPL 是 `siren_server` 进程的 stdin 控制台。启动服务端后，终端里的 `>>>` 提示符用于管理在线客户端、打开交互式 Shell 和执行单条远程命令。

REPL 必须在 tmux 中运行：服务端读到输入结束（EOF）、`Ctrl+C`、`Ctrl+D` 或执行 `exit` 时会立即关闭，`shell` 命令也依赖 tmux。详见 [保持服务端运行](/server#保持服务端运行)。

<Callout title="日常操作用 Web 控制台" type="info">
  下表中大部分命令在 [Web 控制台](/webui) 都有等价入口，且更易用。本页是命令语法参考；具体操作流程见各功能指南。只有标注 **仅 REPL** 的命令没有 WebUI 等价入口。
</Callout>

## 命令速查

在 REPL 中输入 `help` 查看分类帮助，`help <命令>` 查看单个命令的用法。

| 命令 | 用法 | 说明 | WebUI 等价 |
| --- | --- | --- | --- |
| `ls` | `ls` | 列出所有已连接客户端 | [Clients 页](/clients) |
| `note` | `note <Client ID> [Note]` | 设置客户端备注，省略内容则清空 | [Clients 页](/clients) |
| `allow` | `allow <IP>` | 放行受害主机出口 IP 访问服务端 | [出站放行](/onboard/egress) |
| `deploy` | `deploy <UID> <Instance ID> [Public IP]` | 通过云助手部署客户端 | [一键部署](/onboard/provisioning) |
| `deploy-batch` | `deploy-batch <UID> <instanceId[,publicIp[,note]]>...` | 批量部署 2–20 台客户端 | [一键部署](/onboard/provisioning) |
| `shell` | `shell <Client ID>` | 打开交互式远程 Shell | [Shells 页](/shells) |
| `run` | `run <Client ID> <Command>` | 执行单条命令并返回结果 | [Shells 页](/shells) |
| `recon` | `recon <Client ID> [Profile]` | 启动信息收集，省略时用客户端默认 Profile | [信息收集](/recon) |
| `ak` | `ak <UID> <AccessKey ID> [Region]` | 调查 AccessKey 调用历史（默认 `cn-hangzhou`） | [AccessKey 调查](/ak) |
| `info` | `info <Client ID> <PID \| -p Port \| -n Name>` | 查看进程详情（仅 Linux 客户端） | [进程分析](/process) |
| `upload` | `upload <Client ID> <Client file path>` | 将客户端文件保存到服务端 Artifacts | **仅 REPL** |
| `clean` | `clean <Client ID>` | 清除痕迹并终止客户端 | [痕迹清除](/cleanup) |
| `reload` | `reload <Client ID>` | 不重连即重新加载客户端配置 | **仅 REPL** |
| `fwd` | `fwd <Client ID> <src_port:target_addr>` | 建立端口转发 | **仅 REPL**（见 [端口转发](/reference/portforward)） |
| `lsfwd` | `lsfwd` | 列出所有端口转发 | **仅 REPL** |
| `stopfwd` | `stopfwd <Forward ID>` | 停止指定端口转发 | **仅 REPL** |
| `plugins` | `plugins <Client ID> [install\|uninstall\|update\|toggle <Name>]` | 列出或管理客户端插件 | **仅 REPL**（见 [插件](/reference/plugins)） |
| `!` | `! <Command>` | 在服务端本地执行 Shell 命令 | **仅 REPL** |
| `env` | `env <KEY>=<VALUE>` | 设置服务端进程环境变量 | **仅 REPL** |
| `clear` | `clear` | 清屏 | — |
| `help` | `help [command]` | 查看帮助 | — |
| `exit` | `exit` | 退出并关闭服务端 | — |

未识别的首个单词会被当作客户端 [插件命令](/reference/plugins) 匹配（语法 `<插件名> <Client ID> [args...]`）；匹配不到时打印帮助。

| 命令 | 输出位置 |
| --- | --- |
| `ls` `lsfwd` `note` `plugins` `help` `!` `env` | 直接打印在 REPL 终端 |
| `run` | 返回 REPL 终端，最多显示前 50 KiB，超出部分截断并提示 |
| `info` | 返回 REPL 终端 |
| `recon` | 快照与报告写入服务端 Artifacts（Project 取证目录），完成后在 REPL 打印路径；见 [信息收集](/recon) |

| `allow` `deploy` `deploy-batch` | 分步进度打印在 REPL 终端 |

## 客户端管理

客户端通过 TLS 加密通道连接服务端。首次连接时，服务端按客户端稳定身份分配一个数字 `Client ID` 并持久保存，后续 REPL 命令都用这个 ID 指定目标客户端。

`Client ID` 在客户端重连和服务端重启后保持不变，也不会分配给其他主机；只有同一身份出现第二个在线连接（如克隆镜像）时，新连接才会临时获得一个不保存的编号。客户端上线时会上报主机名、内网 IP 和阿里云 ECS Instance ID，`ls` 会一并显示，便于对照告警。执行操作前先用 `ls` 确认目标。

```bash title="siren_server"
>>> ls
```


`note` 为客户端添加备注，省略备注内容时清空：

```bash title="siren_server"
>>> note 0 web-primary
>>> note 0
```

备注支持多个单词（`note 0 db primary` 会完整保留）。备注按客户端稳定身份保存，服务端重启或客户端重连后恢复；WebUI Project 归属也按同一身份恢复。

<Callout title="重连后活动会话不会恢复" type="info">
  稳定身份用于保持 `Client ID`、恢复备注和 Project 归属。交互式 Shell、端口转发和正在执行的命令属于当前连接上的活动会话，服务端重启后需要重新打开。
</Callout>

## 远程命令执行

### 交互式 Shell

`shell` 在服务端通过 `tmux new-window` 打开一个新窗口（命名为 `shell-c<Client ID>`），并把目标客户端的交互式 Shell 接入该窗口，适合连续排查、编辑文件，或运行 `vim`、`top` 这类需要完整终端交互的程序。

```bash title="siren_server"
>>> shell 0
```

Shell 通过一个私有本地套接字中转，客户端经服务端主 TLS 端口（默认 TCP 443）回连，不额外开放随机端口；因此服务端必须安装 `tmux` 并运行在 tmux 中。退出方式与普通终端相同（`exit` 或 `Ctrl+D`），退出后返回 REPL。不想依赖 tmux 时改用 [Shells 页](/shells)。

### 单条命令执行

`run` 执行一次性命令并把输出返回 REPL，适合快速查看当前用户、系统版本、进程列表等。命令在后台执行，执行期间 REPL 仍可输入其他命令；需要持续交互时用 `shell`。

```bash title="siren_server"
>>> run 0 whoami
```

- 单次执行默认超时 30 秒，由客户端配置 `recon.commandTimeout` 决定（见 [客户端配置](/reference/client-config)）；服务端取该值与剩余上下文的较小者。
- REPL 最多显示前 50 KiB 输出，超出部分截断并附提示。客户端侧单次命令最多捕获 16 MiB。
- 长输出建议写入文件后用 [Files](/files) 下载，或用 `upload` 保存到 Artifacts。

<Callout title="一次只能跑一条命令（busy 语义）" type="warn">
  客户端对单次命令串行执行：同一客户端已有一条 `run` 在执行时，新的 `run` 立即以 `busy`（`another run is active`）失败。此限制对所有来源一致——REPL、WebUI、MCP 共用同一个客户端执行槽。客户端正在重新加载配置（`reload`）时发起的 `run` 也会以 `busy`（`client configuration change is in progress`）失败。交互式 `shell` 不受此限制。
</Callout>

## 服务端维护

这些命令作用于服务端自身，没有 WebUI 等价入口。

`reload` 让在线客户端重新读取配置文件并刷新 Recon Profile 能力，不需要断开重连。无效 Profile 配置会被拒绝，并保留上一个有效快照；修改**服务端**配置仍需重启服务端。

```bash title="siren_server"
>>> reload 0
```

`!` 前缀在服务端所在主机执行本地 Shell 命令（不在客户端执行），适合查看服务端工作目录、证书文件或运行环境。

```bash title="siren_server"
>>> ! ls -la certs/
```

`env` 设置当前服务端进程的环境变量，变量值里可以包含 `=`。常用于临时配置[访问凭证](/server/prerequisites)。

```bash title="siren_server"
>>> env SOAR_ACCESS_KEY_ID=<YOUR_ACCESS_KEY_ID>
>>> env SOAR_ACCESS_KEY_SECRET=<YOUR_ACCESS_KEY_SECRET>
```

<Callout title="SOAR 凭证自动重新初始化" type="info">
  设置 `SOAR_ACCESS_KEY_ID` / `SOAR_ACCESS_KEY_SECRET` 后，SIREN 会重置 SOAR 客户端，后续调用使用新凭证。兼容的 `ALIBABA_CLOUD_ACCESS_KEY_ID` / `ALIBABA_CLOUD_ACCESS_KEY_SECRET` 也会触发同样逻辑。
</Callout>

<Callout title="进程级配置" type="warn">
  `env` 只影响当前服务端进程，重启后失效。需要持久化时，请在 Shell、systemd、cron 或 `.env` 等启动环境中配置，见 [服务端配置](/reference/server-config)。
</Callout>

## 快捷键

REPL 支持标准行编辑快捷键：

| 按键 | 作用 |
| --- | --- |
| `Tab` | 补全命令名（`help ` 后还可补全子命令） |
| `↑` / `↓` | 浏览历史命令 |
| `Ctrl+A` / `Ctrl+E` | 跳到行首 / 行尾 |
| `Ctrl+U` / `Ctrl+K` | 删除到行首 / 行尾 |
| `Ctrl+W` | 删除前一个单词 |
| `clear` | 清屏（命令，等价于清屏快捷键） |
| `Ctrl+C` / `Ctrl+D` | 关闭 REPL 并停止服务端 |

服务端二进制的启动参数和 `user`、`upgrade` 子命令见 [安装服务端](/server#命令行参数)，参数与配置键的对应见 [服务端配置](/reference/server-config#命令行参数)。
