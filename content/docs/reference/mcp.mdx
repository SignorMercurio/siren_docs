SIREN Server 内置 [MCP](https://modelcontextprotocol.io/) 服务，提供 11 个工具（`save_evidence`、`case_read`、`case_update` 只在 Project 端点提供，`delegate` 只在开启多 Agent 分工的 AIR GUI 会话中提供）：列出客户端、执行命令、保存证据、维护排查清单、派出 worker、触发 Recon、部署 SIREN、放行客户端 IP 和配置出站规则。[Agentic IR](/air) 自动接入它；本页供外部 MCP 客户端接入和排查时查阅。

## 端点

MCP 由 [`server_config.yaml`](/reference/server-config) 中的 `mcp.enabled` 控制（默认 `true`），不受 `webui.enabled` 影响。它与 WebUI、客户端连接共用顶层 `listen` / `port` 的 TLS 端口（默认 `0.0.0.0:443`），只能通过 HTTPS 访问。

| 路径 | 范围 |
| --- | --- |
| `/mcp` | Global：可看到和操作所有在线客户端 |
| `/mcp/project/<id>` | 单个 Project：`ls` 只列该 Project 的客户端；`run`、`run_batch`、`recon` 拒绝其他客户端；命令输出保存到该 Project 目录，见 [结果文件](#结果文件)；`deploy` 新接入的客户端归入该 Project |

`<id>` 是 Project ID（如 `project-3`），即 WebUI 切换到该 Project 后地址栏中的 `?project=` 参数。

拒绝请求时的 HTTP 状态：

| 状态 | 原因 |
| --- | --- |
| `401` | 没有 `Authorization` 头，或凭证无效、已过期、已吊销 |
| `403` | 凭证无权访问该路径，例如 Project 凭证访问 `/mcp` 或其他 Project |
| `404` | 路径中的 Project 不存在 |
| `400` | 路径不是 `/mcp` 或 `/mcp/project/<id>`，或 Project ID 为空白、含 `/` |

<Callout title="不要经回环地址访问" type="warn">
  请求从 `127.0.0.1` 或 `[::1]` 进入而 `Host` 头不是 localhost 时，MCP 返回 `403`（防 DNS 重绑定）；浏览器发起的跨站请求同样被拒绝。在服务端本机访问时，让域名解析到本机的非回环私网地址，`webui.publicURL` 也因此要求这样解析。
</Callout>

## 鉴权

所有 MCP 请求都必须带 `Authorization: Bearer <token>`，WebUI 登录会话不能代替。

| 凭证 | 来源 | 可访问 | 有效期 |
| --- | --- | --- | --- |
| 管理凭证 | 服务端环境变量 `SIREN_MCP_ADMIN_TOKEN` | `/mcp` 和任意 `/mcp/project/<id>` | 长期 |
| AIR 会话凭证 | 每个 AIR 会话启动时签发 | 只能访问会话所在 Project 的路径 | 会话结束时吊销 |
| 群会话凭证 | Raven 用 `SIREN_MCP_RAVEN_TOKEN` 调用 `/api/mcp/group-session` 换取 | 该钉钉群对应 Project 的路径 | 1 小时 |

- `mcp.enabled` 为 `true` 时 `SIREN_MCP_ADMIN_TOKEN` 必须非空，否则服务端启动即退出，报 `MCP requires SIREN_MCP_ADMIN_TOKEN`。不用 MCP 和 AIR 时可设 `mcp.enabled: false`。
- `SIREN_MCP_RAVEN_TOKEN` 可选，只在接入 Raven 钉钉群会话时设置，且必须与 `SIREN_MCP_ADMIN_TOKEN` 不同，否则服务端拒绝启动。每个钉钉群第一次换取凭证时自动创建一个绑定该群的 Project，群名未知时暂名 `DingTalk <群 ID>`，之后提供群名时改用群名。
- 签发的凭证只存在服务端内存中，重启后全部失效。
- 凭证放在受保护的服务环境文件中，不要写进 `server_config.yaml`、Project 目录、URL 或聊天消息。设置方法见 [MCP 凭证](/server/prerequisites#mcp-凭证)，安全含义见 [MCP 鉴权](/server/security#mcp-鉴权)。

### AIR 会话的凭证

AIR 会话（GUI 或 Terminal）只能在 Project 中启动，MCP 地址由 `webui.publicURL` 加 `/mcp/project/<id>` 拼成。`webui.publicURL` 为空或不是纯 HTTPS Origin 时会话无法启动，分别报 `webui.publicURL is required for AIR MCP`、`webui.publicURL must be an absolute https URL` 或 `webui.publicURL must contain only an https origin`。

Provider 进程不会继承 `SIREN_MCP_ADMIN_TOKEN` 等长期 MCP 凭证，只拿到本会话凭证，且该凭证不会出现在命令行参数或 Provider 的持久配置中。SIREN 不预先放行任何 MCP 工具，调用前是否确认由 Provider 自身配置决定，见 [审批](/air/providers#审批)。

## 接入外部 MCP 客户端

在 MCP 客户端中添加 HTTP 类型的服务器，地址指向 `/mcp`（只操作一个 Project 时用 `/mcp/project/<id>`），并带上管理凭证，建议通过环境变量引用：

```json tab="Claude Code (.mcp.json)"
{
  "mcpServers": {
    "siren": {
      "type": "http",
      "url": "https://siren.example.com/mcp",
      "headers": { "Authorization": "Bearer ${SIREN_MCP_ADMIN_TOKEN}" }
    }
  }
}
```

```toml tab="Codex (config.toml)"
[mcp_servers.siren]
url = "https://siren.example.com/mcp"
bearer_token_env_var = "SIREN_MCP_ADMIN_TOKEN"
tool_timeout_sec = 330
```

`run` 排队和执行合计可超过 4 分钟，`recon` 最长等待 `recon.responseTimeout`（默认 300 秒）。把 MCP 客户端的工具超时设为不少于 330 秒。

运行在 SIREN 服务端以外的客户端无法读取 Recon 的 JSONL 快照文件和 [结果文件](#结果文件)，只能拿到工具返回的摘要、预览和路径。

## 工具

| 工具 | 参数（加粗为必填） | 作用 |
| --- | --- | --- |
| `ls` | 无 | 列出当前范围内的在线客户端 |
| `run` | **`client_id`**、**`command`**、`output_mode`、`timeout_seconds` | 在一台客户端上执行命令 |
| `run_batch` | **`command`**、`client_ids`、`os`、`concurrency`、`timeout_seconds` | 在多台客户端上并发执行同一命令，按主机汇总 |
| `save_evidence` | **`audit_id`**、**`label`**、`stream` | 仅 Project 端点：把 `run` / `run_batch` 的输出从 [结果文件](#结果文件) 原样保存到 Project 的 `evidence/` 目录 |
| `case_read` | 无 | 仅 Project 端点：读取 [Case Board](/air/case-board) |
| `case_update` | `summary`、`items`、`events`、`reports` | 仅 Project 端点：更新当前结论、排查清单和攻击时间线，登记报告覆盖的证据版本 |
| `delegate` | **`item`**、**`prompt`** | 仅开启 [多 Agent 分工](/air/sessions#多-agent-分工) 的 AIR GUI 会话：把一个排查项交给 worker 会话，立即返回 |
| `recon` | **`client_id`**、`profile` | 触发一次 Recon 并等待结果 |
| `deploy` | **`uid`**、**`instance_id`**、`public_ip` | 通过 SOAR 向一台阿里云 ECS 部署 SIREN，等待客户端连接 |
| `allow` | **`ip`** | 在 SIREN 服务端安全组放行一个客户端公网 IP |
| `egress` | **`uid`**、**`instance_id`** | 给一台阿里云 ECS 挂上 SIREN 专用出站安全组，放行它到 SIREN 的出方向访问 |

SIREN MCP 不提供告警查询工具。

### 指定客户端

`client_id` 和 `client_ids` 的每一项可以是数字 Client ID、Instance ID 或主机名（不区分大小写）、任一内网 IP。非数字的值必须在当前范围内唯一匹配一台客户端：匹配多台时报错并列出候选 Client ID，要求改用数字 ID；在 Project 端点上找不到时报 `client not found in current project`。

### `ls`

返回的客户端表含 [Clients 页](/clients) 中填写的备注（`Note`）和客户端支持的 Recon Profile（`Recon Profiles`）。

### `run`

| 参数 | 说明 |
| --- | --- |
| `client_id` | 目标客户端，见 [指定客户端](#指定客户端) |
| `command` | 要执行的命令，最长 50 KiB |
| `output_mode` | `auto`（默认）或 `full`，见 [返回结果](#返回结果) |
| `timeout_seconds` | 命令在客户端上最多运行的秒数，范围 1–120，见 [执行时限](#执行时限) |

命令先经 [命令黑名单](#命令黑名单) 检查；每次调用都写 [审计日志](#审计日志) 并返回 `audit_id`。在 Project 端点上，输出保存为 [结果文件](#结果文件)。标准输出和错误输出合计最多保留 16 MiB，超出部分丢弃并标记捕获不完整。结果只有文本，第一行写明 `audit_id`、`outcome` 等执行信息，见 [结果首行](#结果首行)。时限见 [执行时限](#执行时限)。

`outcome` 的常见取值如下，非 `success` 的结果都以工具错误返回：

| `outcome` | 含义 |
| --- | --- |
| `success` | 执行完毕，退出码为 0 |
| `process_error` | 执行完毕，退出码非 0 |
| `blocked` | 命中命令黑名单，未下发 |
| `rejected` | 目标客户端不存在、不在当前范围或匹配不唯一 |
| `busy` | 该客户端正在执行其他命令，见 [同一客户端的并发](#同一客户端的并发) |
| `timeout` | 超过执行时限 |
| `cancelled` / `canceled` | MCP 请求被取消 |
| `output_limit` | 输出超过 16 MiB |
| `start_error` | 命令未能启动 |
| `transport_error`、`disconnected`、`send_error` | 与客户端的通信失败 |
| `memory_limit` | 所有执行中的命令在服务端暂存的输出合计超过 256 MiB |

### `run_batch`

| 参数 | 说明 |
| --- | --- |
| `command` | 要执行的命令，最长 50 KiB |
| `client_ids` | 目标客户端数组，最多 64 项，格式同 `client_id`，重复项自动去重；任一项无法唯一匹配时整批拒绝，不执行任何命令。在 `/mcp` 上必填；在 Project 端点上省略表示该 Project 的全部在线客户端 |
| `os` | 可选，`linux`、`windows` 或 `darwin`（macOS），在选中的客户端中再按系统过滤 |
| `concurrency` | 同时执行的主机数，默认 8，范围 1–16 |
| `timeout_seconds` | 同 `run`，对每台主机生效 |

- 过滤后没有客户端时报 `no connected clients match the request`；超过 64 台时报错，要求用 `client_ids` 缩小范围。
- 黑名单对整条命令检查一次，命中则整批拒绝。
- 每台主机的执行与单次 `run` 相同，各有独立的 `audit_id`；在 Project 端点上各有自己的结果文件。
- 返回逐台汇总：`outcome`、退出码、错误、结果文件路径和最多 1 KiB 的输出预览；所有预览合计最多内联 50 KiB，超出后每台只保留标题行。
- 只有全部主机都失败时才以工具错误返回。

### `save_evidence`

只在 Project 端点（`/mcp/project/<id>`）提供。

| 参数 | 说明 |
| --- | --- |
| `audit_id` | `run` 或 `run_batch` 返回的 `audit_id` |
| `label` | 文件名标签：小写字母、数字和连字符，以字母或数字开头，最长 48 个字符，如 `nginx-access-xxljob` |
| `stream` | 保存哪一路输出，默认 `text`，见 [输出流](#输出流) |

- 从本 Project 的 [结果文件](#结果文件) 读取输出。没有结果文件时报 `run result unavailable in current project: no saved output for this audit_id`；结果文件在 SIREN 写入后被改动过时报 `runs/<audit_id>.txt was changed after SIREN wrote it`。
- 写入 Project 目录下的 `evidence/<完成时间>-<label>-<audit_id 前 8 位>.txt`，文件已存在时报错，不覆盖。
- 文件以 `# SIREN evidence` 开头的文件头记录 `audit_id`、客户端和主机、命令、开始和完成时间、`outcome`、退出码、输出流、是否完整捕获和正文的 SHA-256，以 `# ---` 结束，其后是原样输出。
- 返回文件路径、正文起始行号和行数。引用格式为 `evidence/<文件>#L<n>-L<m>`，行号从文件第一行（含文件头）算起，WebUI 据此在来源卡片中显示摘录，见 [证据与报告](/air/evidence#在时间线中查看来源)。
- 被黑名单拦截或目标被拒绝的调用没有结果文件，不能保存。

### `case_read`

只在 Project 端点提供，没有参数。文本结果列出 [Case Board](/air/case-board) 的当前结论、排查项、攻击时间线事件、它们引用的实体和证据，以及已登记的报告。结构化结果是 `text`、`revision` 和 `evidence_version`。

全文超过 16 KiB 时，文本结果只给概要：当前结论、`open` 和 `blocked` 的排查项、各状态已结项的数量，以及已登记的报告。全文写入 Project 目录下的 `case/board-r<revision>.txt`，每行一条，结构化结果的 `board_path` 给出这个路径。已结项、时间线事件和证据路径按编号（如 `Q12`、`TL03`、`CE07`）在文件里查。同一 revision 的全文不变，文件写入后不再覆盖。

### `case_update`

只在 Project 端点提供。`summary`、`items`、`events` 和 `reports` 至少传一个，一次调用全部成功或全部不生效。被拒时错误信息列出所有出错的项，每条带 `items[i]`、`events[i]` 这类位置；实体和证据引用先查，引用都通过后再查各字段。文本结果末尾列出未结项和还没有排查项的方向。

`summary` 是当前结论，用一至三句写定性和影响。

`items` 每次最多 50 项，不传 `id` 时新建：

| 字段 | 说明 |
| --- | --- |
| `id` | 已有排查项的编号，如 `Q01` |
| `question` | 要回答的问题；新建时必填 |
| `dimension` | `lead`、`entry`、`credentials`、`execution_persistence`、`lateral_assets`、`impact_data`、`response_status`；新建时必填 |
| `owner` | 负责这一项的角色：`lead`、`entry`、`host`、`cloud`，不传表示 `lead`。[`delegate`](#delegate) 按它决定 worker 的角色。worker 只能改分给自己的那一项，它新建的项归 `lead`；worker 不能写 `summary` |
| `state` | `open`、`confirmed`、`refuted`、`gap`、`blocked`，默认 `open` |
| `entities` | 已有实体的 `id`，或新实体的 `kind` 和 `value`。`kind` 为 `host`、`ip`、`domain`、`identity`、`file`、`resource`；`host` 的 `value` 是本 Project 的在线客户端，写法同 `run` 的 `client_id`（Client ID、Instance ID、主机名或内网 IP）。文件路径、本机账号、本机资源可以加 `host`，值是它所在主机，写法相同：同一路径或账号在两台主机上是两个实体，Case Board 显示为 `主机名:路径`。文件哈希、IP 和域名不能加 `host` |
| `evidence` | 证据列表，见下文 |
| `remove_entities`、`remove_evidence` | 先从列表移除的实体、证据编号 |
| `answer` | 证据查实的内容，Case Board 显示为发现。`confirmed`、`refuted`、`gap` 必填 |
| `next_action` | 一个具体的下一步，Case Board 显示在 Next steps。`open`、`blocked` 必填，`blocked` 写明谁要提供什么；排查项关闭时清空 |

`entities`、`evidence` 追加到已有列表。`summary`、`answer`、`next_action` 分别最多 200、120、80 个字符，其他文本字段最长 2,000 字节，列表最多 50 条。部分状态有必填内容：

| 状态 | 必须提供 |
| --- | --- |
| `confirmed`、`refuted` | `answer` 和证据 |
| `gap` | `answer` |
| `open`、`blocked` | `next_action` |

每条证据只用下面一种写法：

- `id`：复用已有证据，如 `CE01`。
- `audit_id` 加 `label`（可选 `stream`）：SIREN 从结果文件把输出原样保存到 `evidence/`，规则同 [`save_evidence`](#save_evidence)，重复提交不会报错。
- `path`：`evidence/` 下的文件，可带行号，如 `evidence/<文件>#L12-L30`。文件头记录的 SHA-256 与正文不符时拒绝。

`events` 记录攻击时间线，每次最多 50 条，不传 `id` 时新建。除 `clock_note`、`reason`、`attack`、`entities`、`evidence`、`items` 外，新建时都要提供。事件不能删除，`entities`、`evidence`、`remove_entities`、`remove_evidence` 的写法同 `items`，`attack` 和 `items` 传入时整体替换：

| 字段 | 说明 |
| --- | --- |
| `id` | 已有事件的编号，如 `TL01` |
| `kind` | `attack`、`detection`、`response`。排查动作不写入 |
| `from`、`to` | 带时区偏移的 RFC 3339 时间，至少传一个。单一时刻两者相同；只传 `to` 表示不晚于，只传 `from` 表示不早于。不能晚于当前时间 24 小时以上 |
| `precision` | `second`、`minute`、`hour`、`day` |
| `original_time` | 来源原文时间 |
| `time_basis` | `record`（日志、审计、告警时间戳）、`process_start`、`file_time`、`derived` |
| `clock_note` | 时区假设、syslog 年份推断或主机时钟偏差 |
| `action` | 一句话描述发生了什么 |
| `status` | `confirmed`、`inferred`、`withdrawn` |
| `reason` | 推断依据或撤回原因 |
| `attack` | `tactic` 和 `technique` 的列表，只用于 `kind` 为 `attack` 的事件。`tactic` 是 ATT&CK v18 战术，如 `initial_access`；`technique` 形如 `T1059.004` |
| `items` | 这条事件回答的排查项编号 |

| 状态 | 必须提供 |
| --- | --- |
| `confirmed` | 实体和证据；`time_basis` 不能是 `file_time` 或 `derived` |
| `inferred` | 证据和 `reason` |
| `withdrawn` | `reason` |

`reports` 登记报告写作时依据的证据版本，每次最多 50 条：

| 字段 | 说明 |
| --- | --- |
| `path` | Project 内的 Dossier 报告路径 |
| `evidence_version` | 写报告前 `case_read` 返回的 `evidence_version` |
| `items` | 可选，报告覆盖的排查项编号，最多 50 个；不传时覆盖整个看板 |

版本不能高于当前版本，同一份报告的版本不能回退。排查项的证据或状态变化、不在 `open` 状态的排查项回答变化，或事件内容变化时，证据版本加 1。报告覆盖的排查项，或关联这些排查项的事件，在登记的版本之后有变化时，报告显示为需要复核；不传 `items` 的报告看整个看板。编号不存在时整批拒绝。修改事件的 `items` 不影响证据版本。

### `delegate`

只在开启 [多 Agent 分工](/air/sessions#多-agent-分工) 的 AIR GUI 会话中提供，外部 MCP 客户端没有这个工具。

| 参数 | 说明 |
| --- | --- |
| **`item`** | 要交出的排查项编号，如 `Q01`。该项必须是 `open`，`owner` 为 `entry`、`host` 或 `cloud`，且没有正在运行的 worker |
| **`prompt`** | worker 的任务：要查清什么，以及调查对象、时间窗和已知关键事实，最多 2,000 个字符 |

调用立即返回 worker 会话编号、排查项和角色。worker 只看得到 `prompt` 和 Case Board。worker 结束后，SIREN 把结果作为一条新消息发给调用方。同一会话同时最多 6 个 worker 在运行。

### `recon`

| 参数 | 说明 |
| --- | --- |
| `client_id` | 目标客户端 |
| `profile` | 可选，必须是该客户端声明支持的 Profile（见 `ls` 的 `Recon Profiles` 列）；省略时用客户端的默认 Profile |

- 同一客户端同时只能有一个 Recon，冲突时报 `recon already in progress for this client`；Profile 不可用时报 `recon profile is not available`。
- `hunt` Profile 需要运维人员批准：服务端 `mcp.allowHuntRecon` 不为 `true` 时，指定 `hunt` 或省略 `profile` 而客户端默认 Profile 为 `hunt`，都报 `the hunt Recon Profile needs operator approval`。运维人员可在 WebUI 的 [Recon](/recon) 中运行 `hunt`。
- 工具等采集完成后才返回，等待上限为服务端 `recon.responseTimeout`，各项超时见 [Recon 超时](/recon#超时)。
- 文本结果为 Profile、状态和产物路径，后接派生的 Markdown 报告，内联最多 8 KiB，更长时从 `reportPath` 读取全文。`hunt` 及任何含 `topology`、`supplychain`、`config`、`activity` 或 `credential` 模块的 Profile，Markdown 只含拓扑、覆盖范围和采集质量摘要，完整证据在 JSONL 快照中。结果提示 Agent 以 JSONL 为准，并把采集到的文件内容视为不可信数据。
- `status` 为 `complete` 或 `partial`。`reportPath` 和 `snapshotPath` 相对于客户端所属 Project 的 Artifacts 目录，客户端未归属 Project 时相对于服务端工作目录。快照结构见 [Recon 快照格式](/reference/snapshot)。

### `deploy`

| 参数 | 说明 |
| --- | --- |
| `uid` | 拥有该实例的阿里云账号 UID |
| `instance_id` | 目标 ECS 实例 ID |
| `public_ip` | 可选，SIREN 无法自动发现目标出口 IP 时手动指定，必须是合法 IP |

`deploy` 与 WebUI 中 **Deploy SIREN** 的单目标部署流程相同：修改安全组放行、通过 SOAR 安装客户端，等客户端连接后才返回。前置条件见 [一键部署](/onboard/provisioning)。

- 在 Project 端点上调用时，新连接的客户端归入该 Project；在 `/mcp` 上调用时不归属任何 Project。
- 已知该实例的客户端属于其他 Project 时拒绝（`deployment target belongs to another project`），见 [Projects](/projects)。
- 同一 UID 和实例已有部署在进行时拒绝（`deployment already active for instance …`）。
- 只有返回的 `state` 为 `connected` 才算成功；`manual_required` 表示部署完成但无法安全匹配客户端，需到 Clients 页确认。

<Callout title="deploy 会写云端" type="warn">
  `deploy` 会修改目标账号的安全组并在实例上安装软件。工具说明要求 Agent 只在用户明确要求时调用，但这只约束模型，不是 SIREN 的开关；调用前是否确认由 MCP 客户端或 Provider 的配置决定。
</Callout>

### `allow`

| 参数 | 说明 |
| --- | --- |
| `ip` | 要放行的客户端公网 IP，必须是合法 IP |

`allow` 与 WebUI 中 [Allow access](/onboard/egress#allow-access) 相同：在 SIREN 服务端安全组放行这个 IP。`deploy` 已经放行它验证过的回连 IP，不需要再调用 `allow`。

### `egress`

| 参数 | 说明 |
| --- | --- |
| `uid` | 拥有该实例的阿里云账号 UID |
| `instance_id` | 目标 ECS 实例 ID |

`egress` 与 WebUI 中 [Configure egress](/onboard/egress) 相同：给实例挂上 SIREN 专用出站安全组，按 `egress.rules` 放行。适用于 `deploy` 报告安装后连不上 SIREN 的实例。

- 返回专用安全组 ID、实例 ID 和规则列表；配置过程中的警告在 `warnings` 中。
- 每次配置留下一条恢复记录，在 WebUI 中用 [Restore egress](/restore-egress) 撤销。MCP 没有恢复工具。

<Callout title="allow 和 egress 会写云端" type="warn">
  两个工具都修改安全组。工具说明要求 Agent 只在用户明确要求、并给出确切 IP 或实例时调用。这只约束模型，不是 SIREN 的开关；调用前是否确认由 MCP 客户端或 Provider 的配置决定。
</Callout>

## 返回结果

`run` 返回给 Agent 的是有界视图：

| `output_mode` | 输出不超过 8 KiB | 8–50 KiB | 超过 50 KiB |
| --- | --- | --- | --- |
| `auto` | 原样返回 | 首尾预览 | 首尾预览 |
| `full` | 原样返回 | 原样返回 | 首尾预览 |

首尾预览保留开头和结尾各约 4 KiB（尽量在换行处切开），并标出省略的字节范围。预览标注为不可信的远端证据，但不清洗 ANSI 转义、控制字符或疑似指令。

在 Project 端点上，预览写明结果文件的路径和输出起始行，Agent 从文件中读取省略的部分。Global 端点不保存输出，需要省略的部分时改用 `output_mode: full` 或范围更小的命令。

### 结果首行

`run` 只返回文本，不返回结构化字段。第一行形如：

```text
SIREN run audit_id=<id>; outcome=success; exit_code=0; file=runs/<id>.txt from line 12
```

| 项 | 含义 |
| --- | --- |
| `audit_id` | 本次执行的 ID，也是审计日志的关联键 |
| `outcome` | 执行结果，见 [`run`](#run) |
| `exit_code` | 进程退出码；命令未执行完时没有 |
| `timed_out` / `cancelled` / `output_limited` | 超时、被取消、输出超过 16 MiB 时出现 |
| `cancel_confirmed` | 超时或取消后，客户端是否确认命令已结束；为 `false` 或缺失时不能断定远端命令已终止 |
| `capture_incomplete` / `capture_error` | 服务端没有完整收到输出时出现 |
| `had_error_records` / `decode_error` | PowerShell 错误流含错误记录 / 错误流解码失败时出现 |
| `failure` / `error` | 执行失败的类别和原因 |
| `file` | 结果文件相对于 Project 目录的路径，即 `runs/<audit_id>.txt`，以及输出开始的行号；Global 端点和写入失败时没有 |
| `storage_error` | 结果文件未能写入的原因，形如 `write_failed: <错误>` |

只有和正常执行不同的项才出现。输出从第二行开始；超时的结果在第二行先给出处理办法（缩小命令范围，或把命令放到后台写文件、之后再读），首尾预览另有一行 `Preview:`，写明展示和省略的字节范围。完整的执行元数据（含两路输出的哈希）记在 [审计日志](#审计日志) 中。

### 结果文件

在 Project 端点（`/mcp/project/<id>`）上，`run` 和 `run_batch` 中每台主机的输出都写入该 Project 目录下的 `runs/<audit_id>.txt`。Project 目录也是该 Project 中 AIR 会话的工作目录，在该 Project 的 [Artifacts](/artifacts) 中可以查看。

- 文件以 `# SIREN evidence` 开头的文件头记录来源、`audit_id`、客户端和主机、命令、开始和完成时间、`outcome`、退出码、是否完整捕获、两路输出的字节数和正文的 SHA-256，以 `# ---` 结束，其后是 `text` 输出，见 [输出流](#输出流)。
- Agent 用自己的文件工具读取和搜索结果文件。工具说明要求 Agent 重新采集同一证据前先搜索 `runs/`。
- SIREN 不自动删除结果文件，服务端重启后文件仍在。
- [`save_evidence`](#save_evidence) 和 [`case_update`](#case_update) 的 `audit_id` 证据从结果文件读取。结果文件在 SIREN 写入后被改动过时，两者都拒绝。
- 每个 Project 端点只读取本 Project 目录中的结果文件。
- Global 端点（`/mcp`）没有 Project 目录，不保存结果文件。
- 被黑名单拦截或目标被拒绝的调用没有结果文件。
- 结果文件写入失败时，命令结果照常返回，并带 `storage_error`。

### 输出流

`save_evidence` 和 `case_update` 的证据用 `stream` 选择保存哪一路输出：

| `stream` | 内容 |
| --- | --- |
| `text` | 默认。标准输出后接 `[stderr]` 分隔行和错误输出；只有一路有内容时就是那一路 |
| `stdout` / `stderr` | 标准输出 / 错误输出；PowerShell CLIXML 错误输出会转换为可读文本 |

## 执行时限

`run` 和 `run_batch` 的单条命令时限由服务端决定：

- 调用传了 `timeout_seconds` 时用它，范围 1–120 秒。
- 没有传时用服务端 `server_config.yaml` 的 `recon.commandTimeout`，默认 30 秒，超过 120 秒时按 120 秒计。模板中没有这个键，需要时自行添加并重启服务端。

客户端 `config.yaml` 的 `recon.commandTimeout` 只作用于 Recon 采集命令和插件，不影响 MCP 命令，见 [客户端配置](/reference/client-config)。客户端一次只执行一条命令，所以只在扫描确实需要时调大时限。

服务端在时限外再多等 10 秒。超时或 MCP 请求被取消时，服务端通知客户端取消命令，客户端是否确认见 `cancel_confirmed`。

## 同一客户端的并发

每台客户端同一时刻只执行一条远程命令，MCP 的 `run` 与 `run_batch` 中的每台主机共用此限制。另一条命令正在执行时，新命令先排队最多 130 秒，即最长时限 120 秒加 10 秒；排队超时或客户端正在重载配置时以 `outcome: busy` 返回：

| 错误信息 | 原因 |
| --- | --- |
| `another run was still active after 2m10s; retry later` | 排队 130 秒后该客户端上仍有命令在执行 |
| `client configuration change is in progress` | 客户端正在重载配置、管理插件或执行清理 |

`run_batch` 中 busy 的主机单独记为失败，其他主机照常执行；等前一条命令结束后重试即可。Recon 有自己的并发限制，不受此影响。

客户端 30 秒内送不出命令完成回复时会断开连接，进行中的文件传输随之中断；已收到的输出仍写入结果文件。

## 命令黑名单

`run` 和 `run_batch` 下发前，用 `server_config.yaml` 中 `mcp.cmdBlacklist` 的正则（Go 语法）逐条检查命令，命中则不下发，返回 `command blocked by policy (matched: <规则>)`。

<Callout title="只作用于 MCP" type="info">
  WebUI 的 Shells 和 Files、Recon、插件以及 AIR 中 Provider 自带的 Shell 工具都不经过黑名单，见 [命令黑名单只作用于 MCP](/server/security#命令黑名单只作用于-mcp)。
</Callout>

默认规则阻断破坏性变更，放行 `cat`、`grep`、`journalctl`、`systemctl status`、`iptables -L` 等常用只读命令：

| 类别 | 默认拦截的命令 |
| --- | --- |
| 删除与清空 | `rm`、`rmdir`、`find … -delete`、`truncate`、`shred` |
| 磁盘与块设备 | `wipefs`、`mkfs*`、`dd of=/dev/…`、重定向或 `tee`、`cp` 写入 `/dev/sd*` 等块设备 |
| 进程与电源 | `kill`、`killall`、`pkill`、`shutdown`、`reboot`、`halt`、`poweroff`、`init 0`–`6` |
| 服务 | `systemctl stop/disable/mask/restart/reload`、`service <名称> stop/restart/reload` |
| 防火墙 | `iptables` / `ip6tables` 的 `-F`、`-X`、`-Z`、`--flush`、`--delete-chain`、`--zero`，`nft flush ruleset` |
| 账号与权限 | `chmod 000`、`chown`、`useradd` / `usermod` / `userdel`、`groupadd` / `groupmod` / `groupdel`、`passwd`、`chpasswd` |
| 痕迹 | `crontab -r`、`history -c` |
| Windows 删除与清空 | `Remove-Item`（`ri`）、`Clear-Content`、`del`、`erase`、`rd` |
| Windows 进程与电源 | `Stop-Process`（`spps`）、`taskkill`、`Stop-Computer`、`Restart-Computer`、`shutdown` |
| Windows 服务 | `Stop-Service`、`Restart-Service`、`Suspend-Service`、`Remove-Service`、`Set-Service`，`sc stop/delete/config/pause`，`net stop` |
| Windows 磁盘与事件日志 | `Format-Volume`、`Clear-Disk`、`Remove-Partition`、`Clear-EventLog`、`Remove-EventLog`、`wevtutil cl` / `clear-log` |
| Windows 账号、计划任务与防火墙 | `New-` / `Remove-` / `Set-` / `Disable-` / `Enable-LocalUser`、`Add-` / `Remove-LocalGroupMember`，带 `/add` 或 `/delete` 的 `net user` / `net localgroup`，`Unregister-ScheduledTask`、带 `/delete` 的 `schtasks`，`Remove-NetFirewallRule`、`Set-NetFirewallProfile`、`netsh advfirewall reset` |

匹配方式：

- 默认规则匹配命令开头或 `;`、`|`、`&`、换行之后的命令名，允许前置 `sudo`。
- Windows 规则不区分大小写，也匹配 `{`、`(` 之后和 `cmd /c`、`cmd /k` 之后的命令名。
- 单引号和双引号中的文本先遮盖再匹配，因此 `echo "rm -rf /tmp/x"` 不会被拦截。POSIX shell 和 PowerShell 对引号结束位置的判断不同，SIREN 按两种方式各检查一次，任一种命中即拦截。
- `sh`、`bash`、`dash`、`zsh`、`ksh` 的 `-c`，`cmd` 的 `/c`、`/k`，以及 `powershell`、`pwsh` 的 `-Command`、`-c` 后跟引号包裹的命令时（POSIX shell 允许前置 `sudo`、`env`），取出这段命令递归检查，因此 `bash -c 'rm -rf /tmp/x'` 和 `powershell -Command "Remove-Item C:\x"` 都会被拦截。

黑名单是防止 Agent 误操作的护栏，不是安全边界：带路径的写法（如 `/bin/rm`）、`xargs`、变量展开、脚本文件或其他解释器都不会命中默认规则。

修改黑名单：

- 误报时只收窄命中的那条规则，不要清空整组。
- 有一条正则无法编译时，`run` 和 `run_batch` 拦截全部命令，返回 `command blocked by policy (matched: invalid mcp.cmdBlacklist pattern "<规则>")`，日志记录一条 `mcp.blacklist_pattern.invalid` 错误；改完后检查日志。
- 配置只在启动时读取，修改后需重启服务端。

## 审计日志

MCP 日志写入服务端日志，组件为 `mcp`，可在 [Logs](/logs) 页按组件筛选后搜索事件名、命令片段、Client ID、`outcome` 或 `audit_id`。

| 事件 | 级别 | 主要字段 |
| --- | --- | --- |
| `mcp.tool.started` | Debug | `tool`、`project` |
| `mcp.tool.finished` | 成功为 Info（`ls` 为 Debug），以 `_error` 结尾的 `outcome`（如 `send_error`、`deploy_error`、`egress_error`）为 Error，其他为 Warning | `tool`、`project`、`outcome`、`duration_ms`、`client_id` |
| `mcp.run.requested` | Info | `audit_id`、`command`、`requested_client_id`、`project`、`tool`（`run` 或 `run_batch`）、`batch_id` |
| `mcp.run.finished` | 成功为 Info，`send_error` 为 Error，其他为 Warning | 同上，另有 `outcome`、`duration_ms`、`client_id`、`timeout_seconds`、`matched_pattern`、`error`；下发过的命令还有 `result_path` |

- `project` 为 Project ID，Global 端点记为 `global`。
- 每次 `run` 写同一 `audit_id` 的一对 `mcp.run.requested` / `mcp.run.finished`，被拦截、目标被拒绝、取消和超时的调用也不例外。
- `run_batch` 每台主机各有一对记录，以 `batch_id` 关联；整批被黑名单拦截时写一条 `mcp.run_batch.blocked`（Warning，含 `command` 和 `matched_pattern`）和 `mcp.tool.finished`；目标解析失败时只有 `mcp.tool.finished`。
- 日志含完整命令，不含命令输出。Project 端点的输出在 `result_path` 指向的 [结果文件](#结果文件) 中。
- Debug 级记录只在 `logging.level` 为 `debug` 时保留。

<Callout title="日志含敏感信息" type="warn">
  审计记录保留完整命令和错误说明，可能含主机路径、进程参数或凭据，且所有已登录的 WebUI 账号都能查看全部日志，见 [Logs 包含敏感信息](/server/security#logs-包含敏感信息)。需要长期留存时，由 systemd 或容器运行时采集服务端输出。
</Callout>
