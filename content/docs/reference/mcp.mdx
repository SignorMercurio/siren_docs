SIREN Server 内置一个 [MCP](https://modelcontextprotocol.io/) 服务，提供 7 个工具：列出客户端、执行命令、回读长输出、触发 Recon 和部署 SIREN。[Agentic IR](/air) 会自动接入它；本页供外部 MCP 客户端接入和排查时查阅。AIR 界面中的用法见 [Agentic IR](/air)。

服务使用无状态的 Streamable HTTP 传输，以 JSON 返回响应，协议版本最高为 `2026-07-28`，也能与使用更早版本的客户端协商。

## 端点

MCP 由 `server_config.yaml` 中的 `mcp.enabled` 控制，默认 `true`，与 `webui.enabled` 相互独立：关闭 WebUI 后 MCP 端点照常可用。它和 WebUI、客户端连接共用顶层 `listen` / `port` 的 TLS 端口（默认 `0.0.0.0:443`），只能通过 HTTPS 访问。

| 路径 | 范围 |
| --- | --- |
| `/mcp` | Global：可以看到和操作所有在线客户端 |
| `/mcp/project/<id>` | 单个 Project：`ls` 只列出该 Project 的客户端；`run`、`run_batch`、`recon` 拒绝其他客户端；结果回读只能读同一端点产生的结果；`deploy` 新接入的客户端归入该 Project |

`<id>` 是 Project ID，形如 `project-3`。在 WebUI 中切换到该 Project 后，浏览器地址栏的 `?project=` 参数就是它。

请求被拒绝时返回的 HTTP 状态：

| 状态 | 原因 |
| --- | --- |
| `401` | 没有 `Authorization` 头，或凭证无效、已过期、已吊销 |
| `403` | 凭证无权访问这个路径，例如 Project 凭证访问 `/mcp` 或其他 Project |
| `404` | 路径中的 Project 不存在 |
| `400` | 路径不是 `/mcp` 或 `/mcp/project/<id>`，或 Project ID 为空白、含 `/` |

<Callout title="不要经回环地址访问" type="warn">
  请求从 `127.0.0.1` 或 `[::1]` 进入、而 `Host` 头不是 localhost 时，MCP 会以 `403` 拒绝（防 DNS 重绑定）。在服务端本机访问时，应让域名解析到本机的非回环私网地址，这也是 `webui.publicURL` 要求这样解析的原因。浏览器发起的跨站请求同样会被拒绝。
</Callout>

## 鉴权

所有 MCP 请求都必须带 `Authorization: Bearer <token>`，WebUI 登录会话不能代替。

| 凭证 | 来源 | 可访问 | 有效期 |
| --- | --- | --- | --- |
| 管理凭证 | 服务端环境变量 `SIREN_MCP_ADMIN_TOKEN` | `/mcp` 和任意 `/mcp/project/<id>` | 长期 |
| AIR 会话凭证 | 每个 AIR 会话启动时签发 | Project 会话只能访问本 Project 的路径，Global 会话只能访问 `/mcp` | 会话结束时吊销 |

- `mcp.enabled` 为 `true` 时，`SIREN_MCP_ADMIN_TOKEN` 必须非空，否则服务端启动即退出，报 `MCP requires SIREN_MCP_ADMIN_TOKEN`。不使用 MCP 和 AIR 时，可以设 `mcp.enabled: false`。
- 签发的凭证只保存在服务端内存中，服务端重启后全部失效。同时有效的签发凭证最多 10,000 个，用满后新的签发会失败。
- 凭证放在受保护的服务环境文件中，不要写进 `server_config.yaml`、Project 目录、URL 或聊天消息。各类凭证的安全含义见 [MCP 鉴权](/server/security#mcp-鉴权)。

### AIR 会话的凭证

每个 AIR 会话（GUI 或 Terminal）启动时，服务端为它签发一个绑定会话范围的凭证，会话结束时立即吊销。MCP 地址由 `webui.publicURL` 加上 `/mcp` 或 `/mcp/project/<id>` 拼成；`webui.publicURL` 为空或不是纯 HTTPS Origin 时，会话无法启动，分别报 `webui.publicURL is required for AIR MCP`、`webui.publicURL must be an absolute https URL` 或 `webui.publicURL must contain only an https origin`。

启动 Provider 进程时，服务端先从继承的环境中删除 `SIREN_MCP_ADMIN_TOKEN` 等长期 MCP 凭证和已有的 `SIREN_AIR_MCP_TOKEN`，再把本会话凭证写入 `SIREN_AIR_MCP_TOKEN`。各 Provider 读取凭证的方式：

| Provider | 注入方式 |
| --- | --- |
| Claude Code | `--mcp-config` 指向系统临时目录中的私有配置文件 `siren-air-mcp-*.json`，其中带 `Authorization` 头；会话结束时删除 |
| Qoder | Terminal 同 Claude Code；GUI 在会话初始化时直接传入带 `Authorization` 头的 MCP 配置 |
| Codex | 命令行参数 `-c mcp_servers.siren.url=…`、`mcp_servers.siren.required=true`、`mcp_servers.siren.bearer_token_env_var="SIREN_AIR_MCP_TOKEN"` |
| Pi | 环境变量 `SIREN_AIR_MCP_URL` 和 `SIREN_AIR_MCP_TOKEN` |

凭证不会出现在命令行参数或 Provider 的持久配置中。SIREN 不会预先放行任何 MCP 工具，调用前是否需要确认由 Provider 自身配置决定，见 [审批](/air/providers#审批)。

## 接入外部 MCP 客户端

在 MCP 客户端中添加 HTTP 类型的服务器，地址指向 `/mcp`（或 `/mcp/project/<id>`，只操作一个 Project），并带上管理凭证。凭证建议通过环境变量引用：

```json tab="Claude Code (.mcp.json)"
{
  "mcpServers": {
    "siren": {
      "type": "http",
      "url": "https://siren.example.com/mcp",
      "headers": { "Authorization": "Bearer ${SIREN_MCP_ADMIN_TOKEN}" }
    }
  }
}
```

```toml tab="Codex (config.toml)"
[mcp_servers.siren]
url = "https://siren.example.com/mcp"
bearer_token_env_var = "SIREN_MCP_ADMIN_TOKEN"
```

管理凭证在 `/mcp/project/<id>` 上同样有效，此时所有工具都按该 Project 限定范围。外部客户端运行在 SIREN 服务端以外时，无法读取 Recon 的 JSONL 快照文件，只能拿到工具返回的摘要和路径。

## 工具

| 工具 | 参数（加粗为必填） | 作用 |
| --- | --- | --- |
| `ls` | 无 | 列出当前范围内的在线客户端 |
| `run` | **`client_id`**、**`command`**、`output_mode` | 在一台客户端上执行命令 |
| `run_batch` | **`command`**、`client_ids`、`os`、`concurrency` | 在多台客户端上并发执行同一命令，按主机汇总 |
| `read_run_result` | **`audit_id`**、`stream`、`offset`、`limit` | 按字节范围回读 `run` / `run_batch` 的原始输出 |
| `search_run_result` | **`audit_id`**、**`query`**、`stream`、`case_sensitive`、`context_lines`、`max_matches` | 在 `run` / `run_batch` 的原始输出中做字面搜索 |
| `recon` | **`client_id`**、`profile` | 触发一次 Recon 并等待结果 |
| `deploy` | **`uid`**、**`instance_id`**、`public_ip` | 通过 SOAR 向一台阿里云 ECS 部署 SIREN，等待客户端连接 |

SIREN MCP 不提供告警查询工具。除 `ls` 外，所有工具的 structured content 都带一个 `text` 字段，内容与文本结果完全一致，供只读取结构化结果的客户端使用。

### 指定客户端

`client_id` 和 `client_ids` 的每一项可以是：

- 数字 Client ID；
- Instance ID 或主机名（不区分大小写）；
- 任一内网 IP。

非数字的值必须在当前范围内唯一匹配一台客户端。匹配多台时报错并列出候选的 Client ID，要求改用数字 ID；在 Project 端点上找不到时报 `client not found in current project`。

### `ls`

返回一张表，列为 `Client ID`、`Client OS`、`Instance ID`、`Private IP`、`Hostname`、`Client Address`、`Note`、`Plugins`、`Recon Profiles`。没有值的列显示 `-`。`Note` 是在 [Clients 页](/clients) 填写的备注。

### `run`

| 参数 | 说明 |
| --- | --- |
| `client_id` | 目标客户端，见 [指定客户端](#指定客户端) |
| `command` | 要执行的命令，最长 50 KiB |
| `output_mode` | `auto` 或 `full`，省略时取服务端 `mcp.runOutputMode`（默认 `auto`）。返回方式见 [长结果回读](#长结果回读) |

执行顺序：检查 [命令黑名单](#命令黑名单) → 解析目标客户端 → 下发执行。每次调用都会写 [审计日志](#审计日志)，并返回一个 `audit_id`。标准输出和错误输出分开捕获，合计最多保留 16 MiB，超出部分丢弃并标记捕获不完整。执行时限见 [执行时限](#执行时限)。

结果的 `outcome` 常见取值：

| `outcome` | 含义 |
| --- | --- |
| `success` | 命令执行完毕且退出码为 0 |
| `process_error` | 命令执行完毕，退出码非 0 |
| `blocked` | 命中命令黑名单，未下发 |
| `rejected` | 目标客户端不存在、不在当前范围或匹配不唯一 |
| `busy` | 该客户端正在执行其他命令，见 [同一客户端的并发](#同一客户端的并发) |
| `timeout` | 超过执行时限 |
| `cancelled` / `canceled` | MCP 请求被取消 |
| `output_limit` | 输出超过 16 MiB |
| `start_error` | 命令未能启动 |
| `transport_error`、`disconnected`、`send_error` | 与客户端的通信失败 |
| `storage_full` | 服务端结果存储已满，见 [结果保存](#结果保存) |

非 `success` 的结果都以工具错误返回。

### `run_batch`

| 参数 | 说明 |
| --- | --- |
| `command` | 要执行的命令，最长 50 KiB |
| `client_ids` | 目标客户端数组，最多 64 项，格式同 `client_id`。任一项无法唯一匹配时整批拒绝，不执行任何命令。重复项自动去重。在 `/mcp` 上必填；在 Project 端点上省略表示该 Project 的全部在线客户端 |
| `os` | 可选，`linux` 或 `windows`，在选中的客户端中再按系统过滤 |
| `concurrency` | 同时执行的主机数，默认 8，范围 1–16 |

- 过滤后没有客户端时报 `no connected clients match the request`；超过 64 台时报错，要求用 `client_ids` 缩小范围。
- 黑名单对整条命令检查一次，命中时整批拒绝。
- 每台主机的执行与单次 `run` 相同，各自有独立的 `audit_id`，可用于回读和搜索。
- 返回按 Client ID 排序的逐台汇总：`outcome`、退出码、错误，以及最多 1 KiB 的输出预览；所有主机的预览合计最多内联 50 KiB，超出后只保留每台的标题行。structured content 包含 `batch_id`、`project`、`total`、`succeeded`、`failed` 和 `results` 数组。
- 只有全部主机都失败时才以工具错误返回。

### `read_run_result`

| 参数 | 说明 |
| --- | --- |
| `audit_id` | `run` 或 `run_batch` 返回的 `audit_id` |
| `stream` | 读取哪一路输出，默认 `text`，见 [输出流](#输出流) |
| `offset` | 起始字节位置，默认 0；超过结果长度时报错 |
| `limit` | 最多返回的字节数，默认 8 KiB，最大 16 KiB |

文本流的读取范围会对齐到 UTF-8 字符边界，实际范围、`next_offset`、`total_bytes` 和 `complete`（是否已读到已保存数据的末尾）在 structured content 中返回。读取 `raw_stdout` / `raw_stderr` 时，原始字节以 Base64 放在 `content_base64` 中，并附带整路输出的 `sha256`。

### `search_run_result`

| 参数 | 说明 |
| --- | --- |
| `audit_id` | `run` 或 `run_batch` 返回的 `audit_id` |
| `query` | 要查找的字面文本，1 字节到 1 KiB，不支持正则 |
| `stream` | 搜索哪一路输出，默认 `text` |
| `case_sensitive` | 是否区分大小写，默认 `false` |
| `context_lines` | 每个匹配前后附带的行数，默认 2，范围 0–10 |
| `max_matches` | 最多返回的匹配数，默认 20，范围 1–20 |

每个匹配返回字节范围、行号和上下文范围。返回正文最多 8 KiB，放不下时截断上下文并停止，`truncated` 为 `true`；`total_matches` 给出全部匹配数。

### `recon`

| 参数 | 说明 |
| --- | --- |
| `client_id` | 目标客户端 |
| `profile` | 可选，必须是该客户端声明支持的 Profile（见 `ls` 的 `Recon Profiles` 列）；省略时使用客户端的默认 Profile |

- 同一客户端同时只能有一个 Recon，冲突时报 `recon already in progress for this client`；Profile 不可用时报 `recon profile is not available`。
- 工具等待采集完成后返回，等待上限是服务端 `recon.responseTimeout`。各项超时见 [Recon 超时](/recon#超时)。
- 文本结果是 Profile、状态和产物路径，后接派生的 Markdown 报告，内联部分最多 2 MiB。`hunt` 的 Markdown 只含拓扑、覆盖范围和采集质量摘要，完整证据在 JSONL 快照中。
- structured content：`profile`、`status`（`complete` 或 `partial`）、`reportPath`、`snapshotPath`、`format`（`snapshot-jsonl-v2`）、`schemaVersion`。两个路径相对于客户端所属 Project 的 Artifacts 目录；客户端未归属 Project 时相对于服务端工作目录。快照结构见 [Recon 快照格式](/reference/snapshot)。

### `deploy`

| 参数 | 说明 |
| --- | --- |
| `uid` | 拥有该实例的阿里云账号 UID |
| `instance_id` | 目标 ECS 实例 ID |
| `public_ip` | 可选，SIREN 无法自动发现目标出口 IP 时手动指定，必须是合法 IP |

`deploy` 与 WebUI 中 **Deploy SIREN** 的单目标部署走同一流程：修改安全组放行、通过 SOAR 安装客户端，并等待客户端连接后才返回。流程和前置条件见 [一键部署](/onboard/provisioning)。

- 在 Project 端点上调用时，新连接的客户端归入该 Project；在 `/mcp` 上调用时不归属任何 Project。
- 已知该实例的客户端属于其他 Project 时，提交前即拒绝（`deployment target belongs to another project`）；客户端连接后绑定时会再次检查，冲突时保留原归属，需要人工处理。
- 同一 UID 和实例已有部署在进行时拒绝（`deployment already active for instance …`）。
- 返回 `operation_id`、`outcome`、`state`、`client_id`、`warnings` 和 `error`。只有 `state` 为 `connected` 时才算成功；`manual_required` 表示部署完成但无法安全匹配客户端，需要到 Clients 页确认。

<Callout title="deploy 会写云端" type="warn">
  `deploy` 会修改目标账号的安全组并在实例上安装软件。工具说明要求 Agent 只在用户明确要求部署到这台实例时调用，不能把调查或诊断请求当作授权。这是给模型的约束，不是 SIREN 的开关；是否在调用前请求确认由 MCP 客户端或 Provider 的配置决定。
</Callout>

## 长结果回读

`run` 返回给 Agent 的是有界视图，原始输出保存在服务端，可用 `read_run_result` 和 `search_run_result` 按 `audit_id` 回读。回读只读取已经收到的结果，不会在主机上重新执行命令。

| `output_mode` | 输出不超过 8 KiB | 8–50 KiB | 超过 50 KiB |
| --- | --- | --- | --- |
| `auto` | 原样返回 | 首尾预览 | 首尾预览 |
| `full` | 原样返回 | 原样返回 | 首尾预览 |

首尾预览保留开头和结尾各约 4 KiB（尽量在换行处切开），并标出省略的字节范围。预览、回读和搜索返回的内容都标注为不可信的远端证据，但不会清洗 ANSI 转义、控制字符或疑似指令。

### 结果字段

| 字段 | 含义 |
| --- | --- |
| `audit_id` | 本次执行的 ID，也是审计日志的关联键 |
| `outcome` | 执行结果，见 [`run`](#run) |
| `original_bytes` / `returned_bytes` | 原始长度 / 本次返回的长度 |
| `preview_strategy` | `full`（完整返回）或 `head_tail`（首尾预览） |
| `shown_ranges` / `omitted_ranges` | 已展示 / 已省略的字节范围 |
| `preview_complete` | 预览是否完整展示了原始输出 |
| `capture_complete` | 服务端是否完整收到了输出 |
| `complete` | 只有以上两项都为真时才为真 |
| `cancel_confirmed` | 超时或取消后，客户端是否确认命令已结束；为 `false` 或缺失时，不能断定远端命令已终止 |
| `execution` | 退出码、PowerShell 错误记录、各路输出的字节数与 SHA-256 等执行证据 |
| `expires_at` | 结果的过期时间 |
| `storage_error` | 结果未能保存的原因，如 `storage_full` |

退出码和 PowerShell 错误记录分开报告：退出码非 0 的命令，输出也可能完整捕获。

### 输出流

| `stream` | 内容 |
| --- | --- |
| `text` | 默认。标准输出后接 `[stderr]` 分隔行和错误输出；只有一路有内容时就是那一路 |
| `stdout` / `raw_stdout` | 标准输出；`raw_` 版本以 Base64 返回精确字节 |
| `stderr` | 错误输出。能解析的 PowerShell CLIXML 会转换为可读文本 |
| `raw_stderr` | 未经转换的错误输出原始字节 |

命令被黑名单拦截或目标被拒绝时没有执行输出，只能读 `text`。

### 结果保存

- 结果只保存在服务端进程内存中，创建后 60 分钟过期，读取不会续期；服务端重启后清空。
- 总量上限 512 条或 32 MiB，超出时从最早的结果开始淘汰；正在执行的命令也计入上限。
- 结果按端点隔离：只能在产生它的同一端点上读取，Global 与各 Project 互不可读，管理凭证也不例外。
- 已过期、已淘汰、不存在或属于其他范围的结果，都报 `run result unavailable in current project: not_found`。

## 执行时限

`run` 和 `run_batch` 的单条命令时限取以下两者中较小的值：

| 配置项 | 位置 | 默认 |
| --- | --- | --- |
| `recon.commandTimeout` | 客户端 `config.yaml` | 30 秒 |
| `recon.commandTimeout` | 服务端 `server_config.yaml`（模板中没有，需要时自行添加） | 30 秒 |

只调大客户端的值不会让 MCP 命令运行超过 30 秒，需要同时在服务端配置中加上同名键并重启服务端。客户端的同一个值也用于 Recon 的单条采集命令，见 [客户端配置](/reference/client-config)。

服务端在时限之外再多等 10 秒。超时或 MCP 请求被取消时，服务端向客户端发送取消，最多再等 2 秒确认，结果中的 `cancel_confirmed` 说明是否确认。

## 同一客户端的并发

每台客户端同一时刻只执行一条远程命令。MCP 的 `run`、`run_batch` 中的每台主机，以及服务端 REPL 的 `run` 共用这个限制。冲突时不排队，立即以 `outcome: busy` 返回：

| 错误信息 | 原因 |
| --- | --- |
| `another run is active` | 该客户端上已有命令在执行 |
| `client configuration change is in progress` | 客户端正在重载配置、管理插件或执行清理 |

`run_batch` 中遇到 busy 的主机单独记为失败，其他主机照常执行。等前一条命令结束后重试即可。Recon 有自己的并发限制，不受此影响。

客户端在命令结束后排队发送完成回复。回复 30 秒内仍无法送出时，客户端会断开连接，正在进行的文件传输也会中断；已收到的输出仍按捕获状态保存，可以回读。

## 命令黑名单

`run` 和 `run_batch` 下发前，用 `server_config.yaml` 中 `mcp.cmdBlacklist` 的正则（Go 语法）逐条检查命令，命中时不下发，返回 `command blocked by policy (matched: <规则>)`。

<Callout title="只作用于 MCP" type="info">
  黑名单只检查 MCP 的 `run` 和 `run_batch`。服务端 REPL 的 `run` 和 `shell`、WebUI 的 Shells 和 Files、Recon 与插件，以及 AIR 中 Provider 自带的 Shell 工具都不经过它。详见 [命令黑名单只作用于 MCP](/server/security#命令黑名单只作用于-mcp)。
</Callout>

默认规则阻断破坏性变更，保留 `cat`、`grep`、`journalctl`、`systemctl status`、`iptables -L` 等常用只读命令：

| 类别 | 默认拦截的命令 |
| --- | --- |
| 删除与清空 | `rm`、`rmdir`、`find … -delete`、`truncate`、`shred` |
| 磁盘与块设备 | `wipefs`、`mkfs*`、`dd of=/dev/…`、重定向或 `tee`、`cp` 写入 `/dev/sd*` 等块设备 |
| 进程与电源 | `kill`、`killall`、`pkill`、`shutdown`、`reboot`、`halt`、`poweroff`、`init 0`–`6` |
| 服务 | `systemctl stop/disable/mask/restart/reload`、`service <名称> stop/restart/reload` |
| 防火墙 | `iptables` / `ip6tables` 的 `-F`、`-X`、`-Z`、`--flush`、`--delete-chain`、`--zero`，`nft flush ruleset` |
| 账号与权限 | `chmod 000`、`chown`、`useradd` / `usermod` / `userdel`、`groupadd` / `groupmod` / `groupdel`、`passwd`、`chpasswd` |
| 痕迹 | `crontab -r`、`history -c` |

匹配方式：

- 默认规则匹配命令开头或 `;`、`|`、`&`、换行之后的命令名，允许前置 `sudo`。
- 单引号和双引号中的文本先被遮盖再匹配，因此 `echo "rm -rf /tmp/x"` 不会被拦截。
- `sh`、`bash`、`dash`、`zsh`、`ksh` 的 `-c` 后跟引号包裹的命令时（允许前置 `sudo`、`env`），会取出这段命令递归检查，因此 `bash -c 'rm -rf /tmp/x'` 会被拦截。

黑名单是防止 Agent 误操作的护栏，不是安全边界：带路径的写法（如 `/bin/rm`）、`xargs`、变量展开、脚本文件或其他解释器都不会命中默认规则。

修改黑名单：

- 遇到误报时只收窄命中的那条规则，不要清空整组。
- 无法编译的正则会被跳过，并在每次 MCP 请求时记录一条 `mcp.blacklist_pattern.invalid` 警告。改完后检查日志，确认没有规则被跳过。
- 配置只在启动时读取，修改后需要重启服务端。

## 审计日志

MCP 的日志记录在服务端日志中，组件为 `mcp`，可以在 [Logs](/logs) 页按组件筛选后搜索事件名、命令片段、Client ID、`outcome` 或 `audit_id`。

| 事件 | 级别 | 主要字段 |
| --- | --- | --- |
| `mcp.tool.started` | Debug | `tool`、`project` |
| `mcp.tool.finished` | 成功为 Info（`ls` 为 Debug），`send_error` / `deploy_error` 为 Error，其他为 Warning | `tool`、`project`、`outcome`、`duration_ms`、`client_id` |
| `mcp.run.requested` | Info | `audit_id`、`command`、`requested_client_id`、`project`、`tool`（`run` 或 `run_batch`）、`batch_id` |
| `mcp.run.finished` | 成功为 Info，`send_error` 为 Error，其他为 Warning | 同上，另有 `outcome`、`duration_ms`、`client_id`、`matched_pattern`、`error`、`execution`、`result_bytes`、`cache_expires_at`、`storage_error`、`result_retention_seconds` |

- `project` 为 Project ID，Global 端点记为 `global`。
- `run` 在参数校验通过后、黑名单检查前写入 `mcp.run.requested`，结束时写入同一 `audit_id` 的 `mcp.run.finished`。被拦截、目标被拒绝、发送失败、取消和超时的调用都有完成记录。
- `run_batch` 每台主机各有一对记录，用 `batch_id` 关联；整批被黑名单拦截或目标解析失败时只有 `mcp.tool.finished`。
- 日志包含完整命令，但不包含命令输出；输出需要在 60 分钟内用 `read_run_result` 回读。
- Debug 级记录只在 `logging.level` 为 `debug` 时保留。

<Callout title="日志含敏感信息" type="warn">
  审计记录保留完整命令和错误说明，可能包含主机路径、进程参数或凭据。所有已登录的 WebUI 账号都能查看全部日志，见 [Logs 包含敏感信息](/server/security#logs-包含敏感信息)。需要长期留存时，由 systemd 或容器运行时采集服务端输出。
</Callout>
