进程分析无需打开 Shell，即可查看 Linux 客户端上某个进程的父进程链、资源占用、命令行、可执行文件、网络连接、容器和 systemd 服务线索，并标出常见可疑特征。仅支持 Linux 客户端；结果只显示在当前浏览器页面，不写入 Artifacts。

## 打开方式

- 侧栏 **Investigations** → **Process Analysis**。
- [Clients](/clients#行内操作) 页客户端行的 **More actions** → **Process analysis**，预选这台客户端。
- AIR 会话中带进程 ID 的 **Security Center alerts** 结果卡上点 **Inspect PID N**，预选告警主机对应的客户端并预填 **PID**，见 [GUI 时间线](/air/gui#结构化结果卡)。会话所在范围内必须恰好有一台匹配的在线 Linux 客户端，否则提示 `Process evidence needs one connected Linux client in the source workspace.`

## 查询步骤

1. 在 **Client** 中选择客户端。只列出当前范围内的 Linux 客户端；没有时提示 `No Linux clients are currently connected; process analysis needs a Linux client.`
2. 在 **Query type** 中选择 **PID**、**Port** 或 **Name**。
3. 填写查询值，点击 **Analyze**。

| 查询类型 | 填写 | 说明 |
| --- | --- | --- |
| **PID** | 正整数 | |
| **Port** | 1–65535 | 只查 TCP `LISTEN` 端口，取第一个匹配的进程。UDP 端口和已建立的外联连接无法反查 |
| **Name** | 进程名或其中一段 | 支持正则，不匹配命令行参数。多个匹配时先列出候选（最多 50 个），点击候选查看详情 |

Linux 进程名最长 15 个字符，按名称查询以此为准。要按命令行参数查找，先在 [Shell](/shells) 中用 `pgrep -af` 或 `ps` 找到 PID 再查询。

每次查询最多等待客户端 30 秒。页面保留最近 10 条结果，可在 **History** 中切换；刷新浏览器或切换 Project / Global 范围后清空。

## 进程详情

| 区块 | 内容 |
| --- | --- |
| **Parent Chain** | 从最上层祖先到当前进程的父进程链 |
| 概要 | **User**、**State**、**CPU**、**Memory**、**Start** |
| 路径 | **CWD**（工作目录）、**Command**（完整命令行）、**Executable**（可执行文件路径） |
| **Network** | TCP / UDP 连接，按状态（如 `LISTEN`、`ESTAB`）分组，显示本地和远端地址 |
| **Container** | 从 cgroup 识别的 Docker、containerd 或 podman 容器类型和 ID，Docker 另显示名称 |
| **Startup Source** | PID 1 是 systemd 且进程属于某个服务时，显示服务名、状态、描述和 Unit 文件路径 |

CPU 和内存取自 `ps`，CPU 是进程整个生命周期的平均值，不是瞬时值。

### 风险标记

| 标记 | 条件 |
| --- | --- |
| `deleted executable` | 可执行文件路径以 ` (deleted)` 结尾，即程序文件已从磁盘删除 |
| `zombie` | 进程状态为 `Z` |
| `root` | 以 root 运行 |
| `high CPU` | CPU 超过 50% |
| `high memory` | 内存超过 50% |

这些只是排查线索，不代表进程一定恶意。

## 常见问题

**下拉框里没有目标客户端**

确认客户端是 Linux、在线且属于当前 Project；未归属 Project 的客户端只在 Global 范围出现，见 [Project 范围](/projects)。

**按端口查不到进程**

端口查询只认 TCP `LISTEN`。确认端口确实在监听，且主机上有 `ss` 或 `lsof`。

**Network 或 Startup Source 为空**

网络连接依赖 `ss`（缺失时用 `lsof`），服务信息依赖 `systemctl`。缺少这些工具或不是 systemd 系统时，对应区块不显示。

## 命令行

服务端 REPL 和本地模式提供同样的查询，以文本打印。

```bash tab="服务端 REPL"
>>> info <Client ID> <PID>
>>> info <Client ID> -p <Port>
>>> info <Client ID> -n <Process Name>
```

```bash tab="本地模式"
./siren info <PID>
./siren info -p <Port>
./siren info -n <Process Name>
```

- REPL 的 `info` 不支持 Windows 客户端；名称匹配多个进程时打印候选列表（最多 50 个），需再用 PID 查询。见 [服务端 REPL](/reference/repl)。
- 本地模式的 `info` 只在 Linux 版客户端中提供，名称匹配的候选数量不设上限。
