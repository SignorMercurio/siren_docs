客户端接入需要两个方向都通：客户端能向服务端发起连接（出方向），服务端允许客户端出口 IP 连入（入方向）。两项操作都在 Clients 页的 **Provisioning** 面板完成，都依赖 SOAR 访问凭证；Configure egress 还要求服务端配置了 `egress.rules`。见 [前置条件与凭证](/server/prerequisites)。

## Allow access

**Allow access** 通过 SOAR 剧本为客户端公网 IP 添加到服务端回连端口的入方向放行，用于手动安装或自行掌握出口 IP 的场景。一键部署会自动放行探测到的出口 IP，无需单独执行。

1. 在 Provisioning 面板选择 **Allow access** 标签。
2. 每行填一个客户端公网 IPv4 地址，如 `203.0.113.10`，每批 1–20 个。
3. 点击 **Allow N IPs**。逐项执行，单项失败不影响其他项。

逐项结果只保留在当前页面，刷新后消失，也不产生服务端恢复记录。

## Configure egress

对出方向默认拒绝的阿里云 ECS，**Configure egress** 把客户端回连所需的出方向放行加到实例上。

1. 在 Provisioning 面板选择 **Configure egress** 标签。
2. 填写 **Alibaba Cloud UID**，每行填一个 **Instance ID**，每批 1–20 个。
3. 核对面板展示的出站规则（来自服务端配置，只读；加载失败时无法执行）。
4. 点击 **Configure N instances**。逐项执行，结果给出安全组 ID 与地域。

执行时 SIREN 会：

- 创建或复用一个带 `siren:managed` 等标签的专用安全组 `siren-egress-<instanceId>`，以 priority 1 写入出站规则，再挂载到实例上，不移除已有安全组。
- 把实例已有安全组中与这些目的地冲突的 priority-1 Drop 规则降到 priority 2，使放行生效，并记入恢复记录。
- 同一账号下有未完成的操作时，先核对再继续。

<Callout title="规则来自 egress.rules" type="info">
  应用的出站规则完全来自服务端必填配置 `egress.rules`，确认框展示的就是将要授权的规则。默认三条：服务端回连（`siren_server_callback`，TCP 443）、客户端下载（`siren_client_download`，TCP 443）、阿里云基础服务（`alibaba_cloud_infrastructure`，全流量 `100.100.0.0/16`）；最多 20 条。改了服务端监听端口时，同步调整回连规则的端口。字段见 [配置文件](/reference/server-config)。
</Callout>

一键部署自动识别回连 IP 依赖 `egress.discovery`（云防火墙日志库），同样见 [配置文件](/reference/server-config)。

## 持久化与恢复

Configure egress 在服务端保存恢复记录（含被降级的 Drop 规则），刷新页面或服务端重启后仍在。调查结束后用 **Restore egress** 撤销，见 [恢复出站规则](/restore-egress)。出站配置与恢复只能在 WebUI 中操作，没有服务端 REPL 命令或 MCP 工具。

## 客户端出站自检

客户端隐藏命令 `siren probe-egress` 观察一次向服务端的出站 TCP SYN，输出目的 IP、目的端口、源端口和 TCP 序列号，供云防火墙日志出口发现使用，一键部署会在目标主机上自动调用。`--json` 输出结构化证据。仅支持 Linux 和 Windows，需要 root 或管理员权限。

```bash title="目标主机"
./siren probe-egress
./siren probe-egress --json
```
