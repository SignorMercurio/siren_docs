## 版本一致

服务端和客户端必须运行同一版本。两端没有兼容层，SIREN 也不提示版本差异，版本不同时客户端可能连不上或部分操作失败。

查看版本：

- **服务端**：账号菜单 → **Settings**，**Server** 一栏的 **Version**。
- **客户端**：[Clients](/clients#表格列) 页悬停 **Instance ID** 单元格，主机卡片中的 **Version**。
- **命令行**：`siren --version`、`siren_server --version`。

安装脚本、`upgrade` 子命令和一键部署都只取发布地址上的**最新**版本，不能指定版本或降级，所以新版本发布后新接入的客户端就会与旧服务端不一致。服务端启动时检查新版本，有新版本时日志提示 `new version available; run './siren_server upgrade' to upgrade`，看到后尽快把两端一起升级。

## 升级

`upgrade` 子命令有新版本时询问是否升级（`-y` 跳过确认），只替换可执行文件，配置、证书、`data/` 和客户端身份不变。运行中的进程不会切换到新文件，必须重启。

按以下顺序升级，让客户端在服务端重启前就拿到新程序：

<Steps>
<Step>

### 替换客户端程序

服务端仍是旧版本时，在 [Shells](/shells) 中逐台打开客户端的 Shell 执行（手动安装到其他目录的换成实际路径）：

```bash tab="Linux"
/opt/siren/siren upgrade -y
```

```powershell tab="Windows"
C:\Windows\Temp\siren\siren.exe upgrade -y
```

这一步只替换磁盘上的程序，Shell 不会断开。客户端需要能解析并访问发布地址 `oss-siren.oss-cn-hongkong.aliyuncs.com`，否则下载失败。

<Callout title="重新运行安装脚本不会升级客户端" type="warn">
  客户端安装脚本发现已有安装完好时会跳过下载。已安装的主机用 `upgrade` 升级。
</Callout>

</Step>
<Step>

### 升级并重启服务端

```bash title="控制主机"
cd /opt/siren
./siren_server upgrade -y
```

然后 `tmux attach -t siren`，按 `Ctrl+C` 停止旧进程，再执行 `./siren_server`。重启的影响见 [下文](#重启的影响)。

也可以重新运行服务端安装脚本，它保留已有的 `server_config.yaml` 和证书。

</Step>
<Step>

### 重启客户端

已接入的客户端会自动重连新服务端，但进程仍是旧版本，需要重启：

- **一键部署的主机**：在 **Provisioning** 中对这些实例再执行一次 [Deploy SIREN](/onboard/provisioning)。安装脚本跳过下载，停止旧进程，按当前 `siren_server_callback` 规则改写 `config.yaml` 的 `server`、`port`，再用第 1 步的新程序启动；Client ID、Note 和 Project 归属不变。
- **手动启动的客户端**：在主机上停止旧进程，用原命令重新运行 `siren client`。

不要用 **Clean & terminate** 后重新部署代替升级：清理会删除客户端身份，重新部署得到新的 Client ID，原 Note 和 Project 归属不会沿用。

</Step>
<Step>

### 核对版本

Settings 中服务端的 **Version** 应与 Clients 页每台客户端的 **Version** 一致。客户端启动失败时，先看 [升级后核对配置](#升级后核对配置)。

</Step>
</Steps>

### 重启的影响

以下状态只在服务端内存中，重启后清空：WebUI 登录会话（需要重新登录）、Logs 页面缓冲、签发的 MCP 会话凭证、运行中的 Agentic IR 会话、近期部署与清理记录、MCP `run` 结果缓存，以及所有端口转发。

客户端会自动重连并恢复原 Client ID、Note 和 Project 归属，但连续 10 次重连失败（约 5 分钟）后退出，见 [重连行为](/onboard/manual#重连行为)，所以停机时间要尽量短。运行中的 AIR 会话在关闭时结束，之后可以从 History 继续，见 [服务端重启](/air/sessions#服务端重启)。

## 升级后核对配置

`upgrade` 不修改 `server_config.yaml` 和客户端 `config.yaml`，新版本新增的必填项要手动补上，Breaking Change 见 [更新日志](/changelog)。以下配置缺失或无效时会拒绝启动：

| 位置 | 要求 | 报错 |
| --- | --- | --- |
| 服务端 `cert` / `key` | 证书和私钥能加载 | `configure server TLS: ...` |
| 服务端环境变量 | `mcp.enabled` 为 `true`（默认）时，`SIREN_MCP_ADMIN_TOKEN` 非空 | `MCP requires SIREN_MCP_ADMIN_TOKEN` |
| 服务端 `egress.rules` | `webui.enabled` 为 `true`（默认）时，1–20 条有效规则 | `egress.rules...` 开头的错误 |
| 客户端 `recon.profiles`、`recon.defaultProfile` | 都已定义，且默认 Profile 在列表中 | `invalid Recon Profile configuration: ...` |

配置方法见 [前置条件与凭证](/server/prerequisites) 和 [客户端配置](/reference/client-config)。从安装包中取出新版本的配置模板对照：

```bash title="控制主机"
curl -fsSL https://oss-siren.oss-cn-hongkong.aliyuncs.com/siren_server.tar.gz \
  | tar -xzOf - server_config.yaml > /tmp/server_config.new.yaml
diff /opt/siren/server_config.yaml /tmp/server_config.new.yaml
```

客户端模板在 `siren_linux.tar.gz` 的 `config.yaml`。

## 支持的平台

**服务端**只发布 Linux x86_64 版本（`siren_server.tar.gz`），安装脚本在其他架构上直接退出。

**客户端**支持 Linux x86_64、Linux ARM64 和 Windows x64，另有旧内核 Linux 和 Windows 7 时代系统的兼容包，不支持 macOS。安装包与系统版本的对应见 [客户端平台](/onboard#客户端平台)。

## 服务端数据

相对路径按服务端启动时的工作目录（默认 `/opt/siren`）解析。

| 路径 | 内容 |
| --- | --- |
| `server_config.yaml` | 服务端配置 |
| `.env` | MCP、SOAR 等凭证 |
| `certs/` | 默认 TLS 证书和私钥 |
| `data/users.db` | WebUI 账号库，可用 `webui.userDBPath` 改位置 |
| `data/projects.json` | Project 列表、各 Project 目录的绝对路径、客户端归属 |
| `data/client_ids.json` | 客户端身份与 Client ID 的对应关系 |
| `data/client_notes.json` | 客户端 Note |
| `data/egress.json` | **Configure egress** 的恢复记录。丢失后无法再用 [Restore egress](/restore-egress) 撤销已下发的出站规则 |
| `uploads/client-<ID>/` | 服务端 REPL `upload` 拉取的文件 |
| 工作目录中的其他文件 | Global 范围的 Artifacts，例如 Recon 结果和 AccessKey 报告 |
| `webui.projectsBaseDir` 下的子目录 | 各 Project 的 Artifacts 和报告；未设置时位于工作目录下 |
| `webui.dossierDir` | Dossier 静态文件，以及 Blank template 中粘贴的图片 |

Agentic IR 的会话记录由各 Provider CLI 保存在服务端用户自己的目录中（Pi 为 `air.providers.pi.agentDir`），见 [准备 AIR Provider](/server/air-providers)。客户端主机上的文件见 [清理范围](/cleanup#清理范围)。

## 备份

1. 在 tmux 中按 `Ctrl+C` 停止服务端，避免复制时文件正在写入。
2. 打包工作目录，以及位于工作目录之外的 Project 基准目录、`webui.userDBPath`、`webui.dossierDir`：

   ```bash title="控制主机"
   tar -czf /root/siren-backup-$(date +%Y%m%d).tar.gz -C / opt/siren
   ```

3. 需要保留 AIR 会话历史时，一并备份各 Provider 的目录。
4. 重新启动服务端。

备份含 `.env` 凭证和全部取证材料，按敏感数据保管。

## 迁移到另一台主机

<Steps>
<Step>

### 准备新主机

新主机同样需要 Linux x86_64 和 tmux。`siren_server` 随工作目录一起复制，不需要运行安装脚本。

</Step>
<Step>

### 复制数据

按 [备份](#备份) 停止旧服务端并打包，在新主机上解压到**相同的绝对路径**：`data/projects.json` 记录 Project 目录的绝对路径，路径变化后对应 Project 无法访问，见 [基准目录](/projects#基准目录)；各 Provider 也按工作目录保存会话历史，路径不变才能在 History 中继续旧会话。

原样复制 `.env` 且访问域名不变时，外部 MCP 客户端不用改配置。

</Step>
<Step>

### 重建主机相关的部分

以下内容不在工作目录中，需要在新主机上重做：

- 安装并以服务端用户登录 AIR Provider CLI，见 [准备 AIR Provider](/server/air-providers)。
- 在 `/etc/hosts` 中把 `webui.publicURL` 的域名解析到新主机的内网地址，见 [webui.publicURL](/server#webuipublicurl)。
- 证书覆盖新的访问域名，见 [更换证书](/server#更换证书)。

</Step>
<Step>

### 处理网络地址

尽量保留原公网 IP，例如把弹性公网 IP 转绑到新主机。客户端连接的地址在启动时已确定：手动启动的取 `-s` 参数或 `config.yaml` 中的 `server`；一键部署的取部署时 `siren_server_callback` 规则中的地址，已写入其 `config.yaml`。

公网 IP 变化后，已接入的客户端重连失败会退出。先把 `egress.rules` 中 `siren_server_callback` 的 `destCidrIp` 改成新地址，再对一键部署的主机在新服务端上重新执行 [Deploy SIREN](/onboard/provisioning)（写入新地址并重启客户端，身份不变），手动启动的客户端在主机上改地址重启。已执行过 **Configure egress** 的实例，出站安全组仍只放行旧地址；新主机的入方向也要重新放行这些客户端的出口 IP。

</Step>
<Step>

### 启动并核对

在 tmux 中启动服务端，在 Settings 中确认 **Authentication**、**Dossier** 和 **AIR runtime** 正常，在 Clients 页确认客户端以原 Client ID 重新上线。

</Step>
</Steps>
