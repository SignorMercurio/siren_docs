Agentic 应急响应（Agentic IR，简称 AIR）把 Codex、Claude Code、Pi 或 Qoder 接入 SIREN 的调查现场：Agent 读取你给出的告警或任务，通过 SIREN MCP 在在线客户端上执行排查命令、触发 Recon，并协助整理 Markdown 报告。

AIR 是交互式会话，不是无人值守的自动处置。操作员需要盯着执行过程、回答审批和提问、随时补充方向或停止会话，并在写入报告前核对结论。

## 工作方式

- **Provider 跑在服务端**：在 WebUI 的 **Agentic IR** 页面启动会话后，SIREN 在服务端以 `siren_server` 进程的系统用户启动对应 CLI，浏览器只负责显示和输入。刷新或离开页面不会中断会话。
- **SIREN MCP 按范围注入**：每个会话都会注入名为 `siren` 的 MCP Server。Global 视图使用 `/mcp`，可访问全部客户端；Project 视图使用 `/mcp/project/<id>`，只能访问本 Project 的客户端。会话的工作目录同样随范围切换，见 [启动与管理会话](/air/sessions#project-范围)。
- **两种界面**：**GUI** 是按轮次组织的结构化时间线；**Terminal** 运行 Provider 原生的 TUI。启动前选择，会话运行期间不能切换。

AIR 只能在 WebUI 中使用，服务端 REPL 和本地模式没有对应入口。

## 前置条件

- 运维人员已在服务端安装并登录至少一个 Provider CLI，启用 MCP 并设置 `webui.publicURL`，见 [准备 AIR Provider](/server/air-providers)。
- Custom 和 Event 模式需要至少一台在线客户端，见 [选择接入方式](/onboard)。
- 使用 Event 模式时，Provider 自身需要具备查询阿里云安全中心告警的工具或 Skill。SIREN 只把 UID 和事件目标写进开场提示词，不代为查询告警。
- 要从报告卡片直接打开 Dossier 编辑，需要先 [部署 Dossier](/server/dossier)。

## 第一次会话

下面以 Event 模式排查一条安全中心告警为例。

<Steps>
<Step>

### 选择 Provider

打开 **Agentic IR** 页面，在左栏顶部点选一个可用的 Provider；置灰的按钮表示该 Provider 在服务端不可用。保持终端图标未按下，即使用 GUI。

</Step>
<Step>

### 填写 Event 模式并启动

点击 **Event**，选择告警所在主机对应的 **Client**，填写阿里云账号 **UID**，在 **Target** 中保持 **Event** 并填入告警 ID，然后点击 **Start Codex**（按钮名随所选 Provider 变化）。

会话在右侧的新标签中打开，同时出现在左栏 **Running** 列表。其他入口模式和字段规则见 [启动与管理会话](/air/sessions#入口模式)。

</Step>
<Step>

### 观察时间线

Agent 的回复原文与它执行的操作按顺序交错显示，连续操作折叠为摘要行，点击可展开输入和输出。运行中仍可在输入框补充要求调整方向，或单独停止当前这一轮，见 [GUI 时间线](/air/gui)。

</Step>
<Step>

### 回答审批和提问

Provider 要求确认某个操作时，时间线中会出现 **Approval required** 卡片，列出命令、路径或参数，并给出 **Allow once**、**Allow for session**、**Decline** 等选项；Agent 需要你补充信息时会出现提问卡片。审批选项和是否审批因 Provider 而异，见 [Provider 差异](/air/providers)。会话在后台标签中等待时的提示方式见 [启动与管理会话](/air/sessions#待处理提示)。

</Step>
<Step>

### 生成报告并在 Dossier 中编辑

排查告一段落后，让 Agent 把结论整理成 Markdown 报告保存到工作区。报告写入后，时间线中会出现 **Report** 卡片：**Preview** 在 Artifacts 中打开报告，**Edit in Dossier** 在新的浏览器标签页中用 Dossier 打开它继续编辑。Dossier 不可用时该按钮置灰并显示原因。

写入报告前，请逐条核对 Agent 引用的证据，见 [证据与报告](/air/evidence)。

</Step>
</Steps>

## Agent 能做什么

Agent 通过 SIREN MCP 操作客户端，可用工具如下，参数和限制见 [MCP 集成](/mcp#可用工具)：

| 工具 | 用途 |
| --- | --- |
| `ls` | 列出当前范围内的在线客户端 |
| `run` | 在一台客户端上执行命令 |
| `run_batch` | 在多台客户端上并发执行同一命令并按主机汇总 |
| `read_run_result`、`search_run_result` | 回读或搜索长命令输出的原文 |
| `recon` | 在客户端上触发一次 [Recon](/recon)，结果保存到 Artifacts |
| `deploy` | 通过 SOAR 向一台阿里云 ECS 部署 SIREN，并等待客户端连接 |

<Callout title="边界" type="warn">
  - **范围**：Project 会话只能看到和操作本 Project 的客户端。
  - **命令黑名单**：`run` 和 `run_batch` 下发前都会检查 [命令黑名单](/mcp#命令黑名单)，命中时不会执行。
  - **`deploy`**：会修改安全组并在目标主机上安装软件。工具说明要求 Agent 只在你明确要求部署到某台实例时调用，调查或诊断请求本身不构成授权。这是给模型的约束，不是 SIREN 的硬开关；调用前是否需要你审批取决于 Provider 配置。
  - **告警查询**：SIREN MCP 不提供告警查询工具，Event 模式能否拉取告警取决于 Provider 自身的工具或 Skill。
  - **Provider 自带的工具**：Agent 自己的 Shell、文件读写等工具直接在 SIREN 服务端上、以 `siren_server` 的系统用户和会话工作目录执行，不经过 SIREN 的命令黑名单。是否需要审批由各 CLI 的用户配置决定，各 Provider 的差异见 [Provider 差异](/air/providers)。
  - **凭证**：会话只拿到当前范围、随会话结束失效的 MCP 凭证，长期管理凭证不会交给 Provider。
</Callout>
