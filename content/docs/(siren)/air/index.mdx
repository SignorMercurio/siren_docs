Agentic 应急响应（Agentic IR，简称 AIR）让 Codex、Claude Code 或 Pi 通过 SIREN MCP 在在线客户端上执行排查命令、触发 Recon，并协助整理 Markdown 报告。

AIR 是交互式会话，不是无人值守的自动处置：操作员需要盯着执行过程、回答审批和提问、随时补充方向或停止会话，并在写入报告前核对结论。

## 工作方式

- **Provider 跑在服务端**：在 WebUI 的 **Agentic IR** 页面启动会话后，SIREN 以 `siren_server` 进程的系统用户启动对应 CLI。刷新或离开页面不会中断会话。
- **会话属于 Project**：会话只能在 Project 视图中启动。每个会话都注入名为 `siren` 的 MCP Server，只能访问本 Project 的客户端，工作目录是 Project 目录，见 [启动与管理会话](/air/sessions#project-范围)。
- **两种界面**：**GUI**（WebUI 中的 **Chat**）是按轮次组织的结构化时间线，**Terminal** 运行 Provider 原生的 TUI。启动前选择；运行中切换需要先停止会话，再以原会话 ID 继续。

AIR 在 WebUI 中使用。

## 前置条件

- 运维人员已在服务端安装并登录至少一个 Provider CLI，启用 MCP 并设置 `webui.publicURL`，见 [准备 AIR Provider](/server/air-providers)。
- Client 模式需要至少一台在线客户端，见 [选择接入方式](/onboard)。
- Account 模式要求 Provider 自身具备查询阿里云安全中心告警的工具或 Skill；SIREN MCP 不提供告警查询，只把 UID 和时间范围写进开场提示词。
- 要从报告卡片直接打开 Dossier 编辑，需要先 [部署 Dossier](/server/dossier)。

## 第一次会话

下面以 Account 模式排查一个账号的安全中心告警为例。

<Steps>
<Step>

### 选择模型

打开 **Agentic IR** 页面，点击左栏顶部的 **＋**。在表单底部的模型菜单中选一个模型，模型所属的 Provider 随之选定；保持 **Chat**（即使用 GUI）。

</Step>
<Step>

### 填写 Account 模式并启动

点击 **Account**，填写阿里云账号 **UID**，按需调整 **Alert time range**（默认最近 30 天），然后点击 **Start** 或按 `⌘↩`。

{/* Captured at 2x; render at its CSS size so the narrow crop is not enlarged. */}
<ImageZoom src={airStartAccount} width={752} alt="Agentic IR 新建表单的 Account 模式，已填写 UID 并选择 30d 时间范围" />

会话在右侧打开，并出现在左栏的 **Running** 中。其他入口模式见 [启动与管理会话](/air/sessions#入口模式)。

</Step>
<Step>

### 观察时间线

Agent 的回复与操作按顺序显示，点击操作可展开输入和输出。运行中可以在输入框补充要求调整方向，或单独停止当前这一轮，见 [GUI 时间线](/air/gui)。

</Step>
<Step>

### 回答审批和提问

Provider 要求确认操作时，时间线中出现 **Approval required** 卡片，列出命令、路径或参数，并给出 **Allow once**、**Allow for session**、**Decline** 等选项；Agent 需要补充信息时出现提问卡片。选项因 Provider 而异，见 [Provider 差异](/air/providers#审批)；后台会话的提示见 [待处理提示](/air/sessions#待处理提示) 和 [系统通知](/air/sessions#系统通知)。

</Step>
<Step>

### 生成报告并在 Dossier 中编辑

让 Agent 把结论整理成 Markdown 报告保存到工作区后，时间线中出现 **Report** 卡片：**Preview** 在 Artifacts 中打开报告，**Edit in Dossier** 用 Dossier 编辑。

写入报告前，请逐条核对 Agent 引用的证据，见 [证据与报告](/air/evidence)。

</Step>
</Steps>

## Agent 能做什么

Agent 通过 SIREN MCP 操作客户端，参数和限制见 [MCP 集成](/reference/mcp#工具)：

| 工具 | 用途 |
| --- | --- |
| `ls` | 列出当前范围内的在线客户端 |
| `run` | 在一台客户端上执行命令 |
| `run_batch` | 在多台客户端上并发执行同一命令并按主机汇总 |
| `save_evidence` | 仅 Project 会话：把 `run` / `run_batch` 的原始输出原样保存到 `evidence/` 目录，供脚注引用 |
| `case_read`、`case_update` | 仅 Project 会话：维护 [Case Board](/air/case-board) 上的排查清单和攻击时间线 |
| `delegate` | 仅开启 [多 Agent 分工](/air/sessions#多-agent-分工) 的 GUI 会话：把一个排查项交给 worker 会话 |
| `recon` | 在客户端上触发一次 [Recon](/recon)，结果保存到 Artifacts |
| `deploy` | 通过 SOAR 向一台阿里云 ECS 部署 SIREN，并等待客户端连接 |
| `allow` | 在 SIREN 服务端安全组放行一个客户端公网 IP |
| `egress` | 给一台阿里云 ECS 挂上 SIREN 专用出站安全组，放行它到 SIREN 的出方向访问 |

`run` 和 `run_batch` 的完整输出保存在 Project 目录的 `runs/<audit_id>.txt` 中，服务端重启后仍在。Agent 用自己的文件工具读取和搜索这些文件，避免重复取证，见 [结果文件](/reference/mcp#结果文件)。

Project 配置了 [云访问](/consoles) 时，Agent 还可以用 `aliyun` 查询客户账号，用 `opencli` 操作客户云控制台。

<Callout title="边界" type="warn">
  - **范围**：Project 会话只能看到和操作本 Project 的客户端。
  - **命令黑名单**：`run` 和 `run_batch` 下发前检查 [命令黑名单](/reference/mcp#命令黑名单)，命中时不执行。
  - **`deploy`、`allow`、`egress`**：会修改安全组，`deploy` 还会在目标主机上安装软件。工具说明要求 Agent 只在你明确要求对某个 IP 或某台实例执行时调用，调查请求本身不构成授权。这是给模型的约束，不是 SIREN 的硬开关；调用前是否需要审批取决于 Provider 配置。
  - **Provider 自带的工具**：Agent 自己的 Shell、文件读写等工具直接在 SIREN 服务端上、以 `siren_server` 的系统用户和会话工作目录执行，不经过命令黑名单；是否需要审批由各 CLI 的配置决定，见 [Provider 差异](/air/providers)。
  - **凭证**：会话只拿到当前范围、随会话结束失效的 MCP 凭证，长期 MCP 管理凭证不会交给 Provider。本 Project 的阿里云 AccessKey 可由会话中的 `aliyun` 使用。
</Callout>
