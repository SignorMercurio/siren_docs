在 AIR 的 GUI 会话中，SIREN 要求 Agent 为调查结论标注证据来源，并把临时取得的原始输出保存到工作区。本页说明这些要求、来源在界面中的呈现、报告的存放位置，以及把结论写进报告前的核验方法。

<Callout title="只适用于 GUI 会话" type="info">
  证据要求随 GUI 会话注入，四个 Provider 均适用。[Terminal 界面](/air/terminal) 运行 Provider 的原生 TUI，不注入这些要求，回复中通常没有可点击的来源卡片。
</Callout>

## SIREN 对 Agent 的要求

启动或继续 GUI 会话时，SIREN 把一段证据说明附加到 Provider 的系统提示（Codex 为开发者指令）之后。操作者在 CLI 配置或 `args` 中已有的追加提示会保留，SIREN 的说明排在其后。说明的要点如下：

- **用脚注引用**：实质性的调查结论用 Markdown 脚注（`[^1]`）标注来源；普通提问和进度更新不需要。每条回复和每份报告各自包含脚注定义。
- **脚注内容**：依次写明证据摘要、实际数据来源（主机和原始路径，或云账号、日志库、告警或记录 ID）、带时区的采集时间，以及查看原件的位置；日志查询还要写明查询时间范围和时区；行号、记录 ID 或检索词写在链接旁。
- **复用已有材料**：优先引用工作区中已有的 Recon 报告、JSONL 快照等文件。
- **保存临时输出**：依赖临时命令或云端查询的输出之前，在现有权限允许时把原始输出或明确标注的原文摘录保存到工作区的 `evidence/` 目录，文件名带时间戳和唯一后缀，不覆盖已有文件；同时记录来源、采集时间、完整命令或查询语句，以及摘录范围、缺失或截断情况。保存后先读回，再链接。
- **链接写法**：回复中使用相对于工作区的路径，报告中使用相对于报告文件的路径。远程主机上的路径只作为来源描述，不写成本地链接；外部查看只使用真实的 HTTP(S) 地址，否则以文字写出控制台导航路径。
- **不得编造**：只引用实际取得的材料。保存、定位或读取失败时，在脚注中说明缺口并省略不可用的链接。AI 生成的摘要不算原始证据；`audit_id` 可用于追踪，但其结果缓存会过期，不能单独作为查看位置。

这段说明不授予额外权限，也不改变 Provider 的审批策略：Agent 写入 `evidence/` 时，仍按 [审批](/air/providers#审批) 规则请求确认。

## 在时间线中查看来源

带脚注的回复中，编号 `[1]`、`[2]` 可以点击：

- 点击编号打开来源卡片，显示该脚注的全部内容（摘要、来源、采集时间、原件入口），卡片中的链接可直接点击。再次点击编号、点击关闭按钮或按 Esc 关闭。
- 每条回复下方的 **Sources (N)** 可展开该回复的全部来源。
- 回复仍在生成时，编号暂不可点击；回复引用了不存在的脚注定义时，编号保持为普通文本。

来源卡片的内容由 Agent 撰写，SIREN 不验证其真实性。

## 链接如何打开

**回复中的链接**

| 链接 | 行为 |
| --- | --- |
| 工作区相对路径，如 `evidence/20261008-1430-ps-a1b2.txt` | 在该会话所属 Project 的 Artifacts 中打开，即使当前已切换到其他 Project 视图 |
| 指向会话所属 Project 目录内的绝对路径 | 当前视图就是该 Project 时，去掉目录前缀后同上；否则不可点击 |
| `http://` 或 `https://` 地址 | 在新标签页打开 |
| 含 `..`、以 `.` 开头的目录或文件、工作区之外的绝对路径、其他协议 | 不可点击 |

时间线中操作行上的文件路径、结构化结果卡中的报告和快照路径，也按同样的方式在 Artifacts 中打开，只显示工作区内的安全相对路径。

**报告中的链接**

在 [Artifacts](/webui#artifacts) 中预览 Markdown 报告时，报告内的相对链接按报告所在目录解析，可以用 `..` 指向上级目录，但不能超出工作区；点击后在 Artifacts 中打开目标文件。以 `/` 开头的路径和以 `.` 开头的目录或文件不可点击。

## 报告存放位置

Agent 在 Provider 的工作目录中生成报告和 `evidence/` 目录，工作目录由启动会话时的视图决定：

| 视图 | 工作目录 | 在 WebUI 中查看 |
| --- | --- | --- |
| Project | 该 Project 的目录 | 该 Project 的 Artifacts |
| Global | `siren_server` 进程的当前工作目录 | Global 视图的 Artifacts |

Agent 写入或明确链接 `.md` 报告后，该轮末尾会出现 **Report** 卡，提供 **Preview** 和 **Edit in Dossier**，用法见 [GUI 时间线](/air/gui#report-卡)。在 Dossier 中继续编辑和导出报告的流程见 [Dossier 工作流](/dossier/workflow)。

## 导出会话

从状态条导出的 Markdown 文件保留回复中的标准 Markdown 脚注。不同回复的脚注编号会自动加上各自的前缀，导出后不会互相冲突。导出只包含回复中已有的脚注，不会为没有引用的历史回复补齐来源。导出方式见 [GUI 时间线](/air/gui#导出-markdown)。

## 核验结论

脚注说明了 Agent 声称的来源，不等于证据已经核实。把结论写进报告之前，建议逐项检查：

1. **每条关键结论都有脚注**。没有脚注的结论视为未经核实，可以直接追问 Agent 取证并补充来源。
2. **打开原件，而不是只看摘要**。点击来源卡片中的链接，在 Artifacts 中查看 `evidence/` 文件或 Recon 报告，确认摘录与结论一致。
3. **核对采集信息**。检查记录的命令或查询语句、主机、采集时间和时区、日志时间范围，以及是否注明了截断或缺失。
4. **留意脚注中声明的缺口**。注明 “保存失败”“无法定位” 的来源，只能作为线索。
5. **对关键事实独立复核**。必要时在 [Shells](/webui#shells) 或 [Investigations](/webui#investigations) 中自行执行命令或查看进程，不要只依赖 Agent 的转述。安全中心告警卡展示的是数据源返回的等级，不是失陷判定。
6. **核对操作记录**。在时间线中用 **Failed**、**Commands**、**Files** 过滤，确认 Agent 实际执行过、而非只是计划执行的操作，以及是否有失败被忽略。
