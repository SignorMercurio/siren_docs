**Case Board** 是一个 Project 的排查进度看板。AIR 在排查时写入，你在这里查看，页面本身不能修改。它在 **Respond** 分组下，需要先选择 Project。

页面顶部显示 AIR 写的当前结论和各类排查项的数量。AIR 还没写结论时，这里显示未结项数量。

下方分为 **Progress** 和 **Timeline** 两个标签页。

SIREN 会检查 AIR 的写入：没有证据或回答的排查项不能标为 Confirmed 或 Ruled out，未结项必须写下一步，只有文件时间的事件不能标为已确认，参数见 [`case_update`](/reference/mcp#case_update)。

## 排查中：看进度

这部分在 **Progress** 标签页，左边是发现，右边是下一步。

左边按排查方向分组，列出 AIR 已查实和已排除的内容。每组先显示结论最新的 3 条，点击 **Show N more** 查看其余。分组标题前的节点颜色取这个方向最需要处理的状态：红色是有受阻项，灰色是还在排查，黄色是只剩证据缺口，绿色是全部已有结论。标题右侧显示已结项数和总项数。还没有排查项的方向显示 **not started**，排在最后。

查不实的内容（证据缺口）不放在各方向中，统一列在最后的 **Closed without a finding** 组，同样先显示最新的 3 条。

**Hosts with no items** 列出 Project 里还没有排查项或事件提到的主机。

右边的栏在页面滚动时保持可见。**Waiting on you** 列出需要你提供的内容。**Queued** 是 AIR 接下来要做的事。

点击一条可以展开，看到它对应的问题和涉及的实体。文件路径、账号和资源带有所在主机时显示为 `主机名:值`，两台主机上的同名路径是两个实体。证据显示为原文摘录，点击 **Open file** 在 [Artifacts](/artifacts) 中打开完整文件。

写报告前先看是否还有 Blocked、Open 或 Gap，再决定继续排查，还是在报告中说明缺口。

## 排查中：看攻击时间线

这部分在 **Timeline** 标签页，记录这次事件本身发生了什么，包括攻击者动作、客户侧发现和处置。AIR 的排查动作不进时间线。

| 标记 | 含义 |
| --- | --- |
| 红点 | 攻击者动作 |
| 橙点 | 客户侧发现 |
| 绿点 | 客户侧处置 |
| 实心点 | 已确认 |
| 空心点加 **Inferred** | 推断，只有文件时间或由其他事件推出 |

**Time** 视图按时间排列，相隔一天以上时显示间隔。**Tactic** 视图按 ATT&CK 战术分组，一个行为涉及多个战术时会出现在每一组，发现和处置不显示。

时间按浏览器时区显示，只精确到来源给出的程度。只知道边界时显示 `Not before` 或 `Not after`。点击事件可以看到来源原文时间、时间依据、时钟说明和证据摘录。

被推翻、重复或误写的事件不会删除，AIR 把它们标为撤回。点击 **Show N withdrawn** 可以查看。

## 交报告前：看报告是否落后

AIR 写完报告后会登记它。最新登记的报告显示在标签页上方。之后如果排查项的证据、结论或回答有变化，或时间线事件有变化，报告会变成橙色提示：

| 状态 | 含义 |
| --- | --- |
| Up to date | 报告写完后证据、结论和事件没有变化 |
| Evidence changed | 有变化，右侧显示 **N items to review**，点击后按 Progress 和 Timeline 列出变化的编号和内容摘要 |

点击编号可以跳到对应内容并展开。看到 Evidence changed 时，让 AIR 按这些内容修订报告。修订后重新登记，状态回到 Up to date。点击报告文件名可以打开报告，鼠标悬停显示完整路径。

只有最新的报告和看板比对。更早登记的报告列在 **Earlier reports** 一行，点击可以打开，不再提示复核。
