这页解释 WebUI 里反复出现的几个名词，每个名词只给定义和相互关系，具体操作见各自的页面。

```text
SIREN Server（控制主机，WebUI、MCP 和客户端共用一个 TLS 端口，默认 443）
├── WebUI ── 侧栏顶部 Project scope：Global ／ 某个 Project
│   ├── Clients ── Provisioning（Allow access / Configure egress / Restore egress / Deploy SIREN）
│   ├── Agentic IR ── 通过 SIREN MCP 操作客户端
│   ├── Investigations ── Recon / Process Analysis / AccessKey
│   └── Artifacts ⊃ Reports
├── MCP ── /mcp（Global）、/mcp/project/<id>（单个 Project）
└── Client × N ── 每台被调查主机上的客户端，主动回连服务端
```

## SIREN Server 与 Client

**SIREN Server** 运行在控制主机上，同时提供 WebUI、MCP 服务和客户端接入，三者共用顶层 `listen` / `port`。安装步骤见 [安装服务端](/server)。

**Client**（客户端）运行在被调查主机上，主动连接服务端。每个在线客户端在 [Clients 页](/clients) 占一行，几乎所有操作都从这一行开始。

客户端有两个容易混淆的标识：

| | Client ID | 稳定身份 |
| --- | --- | --- |
| 形式 | 数字，显示在 Clients 的 **ID** 列，REPL 和 MCP 用它指定目标 | 客户端首次启动时生成的随机 ID，保存在主机用户配置目录下的 `siren/agent_id` |
| 生命周期 | 客户端重连、客户端重启、服务端重启后都不变，也不会再分配给其他主机 | 身份文件存在期间不变 |
| 绑定的数据 | 无 | Client ID、Note、Project 归属 |

- 同一身份同时出现第二个在线连接（例如从同一镜像克隆的主机）时，新连接会拿到一个临时编号，这个编号不保存。
- **Clean & terminate** 会删除身份文件。之后在同一台主机上重新部署，会生成新身份和新的 Client ID，原来的 Note 和 Project 归属不会带过去。
- 稳定身份只恢复 Note 和 Project 归属。Shell、端口转发和正在执行的命令属于当前连接，断线后需要重新打开。

## Global 与 Project 范围

**Project** 是按事件划分的工作区，包含名称、颜色和服务端上的一个专用目录。每个客户端最多归属一个 Project。

**Global** 是不选 Project 时的范围：能看到所有客户端，也是唯一能给客户端分配 Project 的地方。

侧栏顶部的 **Project scope** 选择器决定当前范围，菜单末尾的 **Manage projects** 进入 Projects 页。范围会影响以下页面：

| 页面 | Global | Project 视图 |
| --- | --- | --- |
| Clients | 全部客户端，可分配 Project | 只列本 Project 的客户端 |
| Shells、Files、Investigations 的 Recon 和 Process Analysis | 可选任意在线客户端 | 只能选本 Project 的客户端 |
| Agentic IR | 工作目录是服务端工作目录，MCP 端点 `/mcp` | 工作目录是 Project 目录，MCP 端点 `/mcp/project/<id>` |
| Artifacts | 根目录是服务端工作目录 | 根目录是 Project 目录 |
| Reports | 汇总服务端工作目录和所有 Project | 只扫描 Project 目录 |
| Investigations 的 AccessKey | 报告写入 Global | 报告仍写入 Global |
| Logs、Settings | 不受范围影响 | 不受范围影响 |

完整规则和例外见 [Project 范围](/projects)。

## Agentic IR 会话

**Agentic IR**（AIR）会话是在服务端运行的 AI 代理，Provider 可选 Codex、Claude、Pi 或 Qoder。代理通过 SIREN MCP 操作客户端，需要审批或提问时会停下来等操作员回应。AIR 只能在 WebUI 中使用，服务端 REPL 没有对应命令。

每个会话有两个维度：

- **界面**：**GUI** 是结构化时间线；**Terminal** 是 Provider 原生的终端界面。
- **入口模式**：只有三种。
  - **Manual**：空白会话，不绑定客户端，也没有种子提示词。
  - **Custom**：选一个客户端并描述要调查的内容。
  - **Event**：选客户端，填写 UID，再选一个目标：告警 **Event**、**ECS** 实例或 Security Center **Asset**。后两种目标可以用 **Time range** 限定告警时间范围。

继续以前的会话不是入口模式：在 AIR 侧栏展开 **History**，打开历史会话（先以只读方式显示），再点 **Continue session** 或 **Continue in Terminal**。

会话托管在服务端，刷新浏览器或切换页面不会中断，回到 AIR 页可以从 **Running** 重新接入。会话的工作目录和 MCP 范围取决于启动时的 Project 范围。详见 [Agentic IR](/air)。

## 调查工具

**Investigations** 页有三个不经过 AI 的确定性工具：

| 工具 | 输入 | 产出 |
| --- | --- | --- |
| **Recon** | 客户端和 Profile（Profile 列表由客户端上报） | `.recon.jsonl` 快照和渲染后的 `.md` 报告，写入该客户端所属 Project 的 Artifacts；未归属时写入 Global |
| **Process Analysis** | Linux 客户端，按 PID、Port 或 Name 查询 | 结果只显示在页面上，不写文件 |
| **AccessKey** | UID、AccessKey ID、可选 Region，经 SOAR 查询云 API 调用记录 | `AK_*.md` 报告，始终写入 Global Artifacts |

AIR 能通过 MCP 的 `recon` 工具执行 Recon。Process Analysis 和 AccessKey 不在 MCP 工具里，只能在 WebUI 中运行。详见 [Recon](/recon)、[进程分析](/process) 和 [AccessKey 调查](/ak)。

## Artifacts 与 Reports

**Artifacts** 是服务端上按范围划分的证据目录：Global 对应服务端工作目录，Project 对应 Project 目录。Recon 结果、AccessKey 报告、AIR 产出和手工上传的文件都在这里。

**Reports** 不是另一个存储位置，而是 Artifacts 中 Dossier 格式报告的列表。一个 `.md` 文件要出现在 Reports 页，文件开头必须是 `---` frontmatter，并同时包含 `date`、`sir-seq`、`version` 和 `client` 四个字段。Recon 生成的 `.md` 和普通笔记不满足这个条件，所以不会列出。Reports 在 Dossier 编辑器中打开，前提是服务端配置了 `webui.dossierDir`。

详见 [Artifacts](/artifacts)、[Reports](/reports) 和 [Dossier 语法](/reports/syntax)。

## Provisioning 与出站恢复

**Provisioning** 是 Clients 页下方的面板，通过 SOAR 剧本操作阿里云 ECS，每次最多 20 个目标：

- **Allow access**：按客户端公网 IPv4 放行其访问 SIREN 服务端。
- **Configure egress**：为出方向默认拒绝的实例放行访问 SIREN 所需的出站流量，规则来自服务端配置 `egress.rules`。
- **Deploy SIREN**：在实例上安装并启动客户端。

**出站恢复**（**Restore egress**）回滚 Configure egress 做过的修改，只撤销 SIREN 自己记录的变更。恢复可能切断客户端回连，所以先 Clean 客户端，再恢复。

详见 [一键部署](/onboard/provisioning)、[出站放行](/onboard/egress) 和 [恢复出站规则](/restore-egress)。

## MCP

SIREN 通过 MCP 把操作客户端的能力提供给 AI 代理，工具包括 `ls`、`run`、`run_batch`、`read_run_result`、`search_run_result`、`recon` 和 `deploy`。端点有两类：`/mcp` 对应 Global，`/mcp/project/<id>` 只能访问一个 Project 的客户端。

- **AIR**：服务端在启动会话时自动注入 SIREN MCP，并签发一个绑定当前范围的会话凭证，会话结束即吊销。不需要在 Provider 配置里手动添加。
- **外部代理**：用 `Authorization: Bearer` 携带服务端环境变量 `SIREN_MCP_ADMIN_TOKEN` 的值访问。WebUI 登录状态不能代替这个凭证。

<Callout type="info">
  MCP 默认启用。启用时服务端环境里必须有两个非空且互不相同的值 `SIREN_MCP_ADMIN_TOKEN` 和 `SIREN_MCP_RAVEN_TOKEN`，否则拒绝启动。准备方式见 [前置条件与凭证](/server/prerequisites)。
</Callout>

详见 [MCP](/reference/mcp) 和 [账号与安全边界](/server/security)。
