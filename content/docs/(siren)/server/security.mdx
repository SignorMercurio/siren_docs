SIREN Server 各入口的鉴权方式不同，部署到公网前请逐条核对。

## 各入口的鉴权方式

| 入口 | 鉴权方式 | 说明 |
| --- | --- | --- |
| Web 控制台页面与 `/api/*` | 登录会话 Cookie | 启动时没有任何账号则完全不鉴权，见 [WebUI 账号](#webui-账号) |
| `/mcp`、`/mcp/project/<id>` | Bearer 凭证 | 与 WebUI 会话无关，关闭 WebUI 后仍然要求，见 [MCP 鉴权](#mcp-鉴权) |
| 托管客户端连接 | 无 | 依靠网络放行控制来源，见 [客户端与服务端之间](#客户端与服务端之间) |
| `/dossier/` | 无 | 见 [`/dossier/` 不鉴权](#dossier-不鉴权) |
| 登录页、前端静态文件、`/api/version` | 无 | 暴露服务端版本号 |
| [端口转发](/reference/portforward)监听端口 | 无 | 在服务端所有网卡上监听，能访问该端口即可连到转发目标 |
| 服务端 REPL | 控制主机终端 | 只能在运行 `siren_server` 的终端中使用 |

## WebUI 账号

账号保存在 SQLite 数据库中，密码以 bcrypt 哈希存储，默认路径为工作目录下的 `data/users.db`，可用 `webui.userDBPath` 指定绝对路径。

```bash title="控制主机"
cd /opt/siren
./siren_server user add <username>      # 交互输入两次密码
./siren_server user list                # 列出 ID、用户名和创建时间
./siren_server user delete <username>
```

`user` 命令读取 `server_config.yaml` 定位账号库，请在服务端工作目录中执行。

<Callout title="没有账号时不鉴权" type="error">
  服务端只在启动时检查账号库。账号库不存在或没有任何账号时，本次运行期间 Web 控制台和所有 `/api/*` 都不需要登录，日志提示 `WebUI auth disabled; run 'siren_server user add'`，Settings 的 **Authentication** 显示 **Disabled (local access)**。创建第一个账号后必须重启服务端才会启用鉴权。
</Callout>

启用鉴权后：

- **添加账号**立即生效，无需重启。
- **没有改密码命令**，先 `user delete` 再 `user add`。
- **删除账号不会让其已登录的会话失效**。会话有效期 30 天，保存在服务端内存中；要立即踢出，需重启服务端，重启后所有会话失效。
- **登录锁定**：同一来源 IP 在 15 分钟内失败 5 次后锁定，直到第一次失败满 15 分钟；锁定期间即使密码正确也显示 **Invalid username or password**。来源 IP 取自 TCP 连接，不读取 `X-Forwarded-For`。

### 账号的权限范围

所有账号权限相同，没有角色区分。Project 是工作区划分，不是权限边界，任何账号都能切换到任意 Project 或 Global 视图。一个 WebUI 账号可以：

- 操作所有在线客户端：Shell、Files 上传覆盖、Recon、清理，以及部署和出站放行等云端写操作。
- 在 Global 视图的 Artifacts 中浏览、下载、上传、重命名和删除服务端工作目录下的文件。状态目录、账号库、配置、证书、二进制和 `.env` 等点号开头的文件受保护，见 [服务端自身文件](/artifacts#服务端自身文件)。
- 查看全部服务端日志，见 [Logs 包含敏感信息](#logs-包含敏感信息)。
- 启动 Agentic IR。Provider CLI 以服务端进程身份运行在控制主机上，其自带的 Shell 和文件工具直接作用于控制主机；审批和沙箱由 Provider 自身配置决定。

因此 WebUI 账号只应发给可以完全信任、相当于控制主机管理员的操作员。

## MCP 鉴权

所有 MCP 请求都必须携带 `Authorization: Bearer <token>`，WebUI 登录会话不能代替。只有管理凭证 `SIREN_MCP_ADMIN_TOKEN` 能访问全局 `/mcp` 和任意 Project；AIR 使用限定到单个范围、随会话吊销的凭证，服务端重启后全部失效。详见 [MCP 鉴权](/reference/mcp#鉴权)。

Agentic IR 启动 Provider CLI 时会从子进程环境中剔除 `SIREN_MCP_ADMIN_TOKEN` 等长期 MCP 凭证，但其他环境变量原样继承，包括 `SOAR_ACCESS_KEY_*` 和 `ALIBABA_CLOUD_ACCESS_KEY_*`。Agent 能在控制主机上执行命令，就能读到这些凭证。

### 命令黑名单只作用于 MCP

`mcp.cmdBlacklist` 只检查 MCP 的 `run` 和 `run_batch`。服务端 REPL 的 `run` 和 `shell`、Web 控制台的 Shells 和 Files、Agentic IR 中 Provider 自带的 Shell 工具（在控制主机上执行）都不受约束。

无法编译的正则会被跳过且服务端照常启动，日志中记录 `mcp.blacklist_pattern.invalid` 警告；修改后请检查日志。匹配方式见 [命令黑名单](/reference/mcp#命令黑名单)。

## `/dossier/` 不鉴权

`webui.dossierDir` 通过 `/dossier/` 作为静态文件提供，不经过 WebUI 登录。没有目录列表，但知道路径的人都能下载其中的文件。

Reports 页面的 **Blank template** 虽然只读，但在其中粘贴的图片会立即写入 `dossierDir/report.assets/pasted/`，无需登录即可访问。不要在 Blank template 中粘贴敏感截图，也不要在 Dossier 目录中存放运行文件以外的内容。从 Artifacts、Reports 或 AIR 报告卡片打开的实际报告不受影响，其图片读取需要登录。

## 客户端与服务端之间

- **客户端不校验服务端证书**。连接使用 TLS 1.2 及以上加密，但客户端接受任何证书，能劫持客户端所连地址的一方可以冒充服务端下发命令。请让客户端直连服务端的固定 IP 或可信的域名解析。
- **客户端接入不需要凭证**。任何能访问主 TLS 端口的主机都能注册为客户端并出现在 Clients 列表中；客户端身份由客户端自行上报，备注和 Project 归属按它恢复。能否连接完全取决于端口的入方向放行，即 **Allow access** 和部署流程维护的规则。

## Logs 包含敏感信息

任何已登录账号都能在 Logs 页面看到全部服务端日志，不按 Project 过滤，包括来访 IP、登录用户名、客户端地址和 MCP `run` 的完整命令。条数由 `logging.bufferSize` 控制，设为 `0` 可完全关闭该页面，见 [日志与审计](/logs)。

## 公网暴露建议

<Callout title="上线前核对" type="warn">
  - 启动前用 `siren_server user add` 创建至少一个账号，启动后在 Settings 中确认 **Authentication** 显示已登录用户。
  - 使用覆盖访问域名、且受浏览器信任的证书，见 [更换证书](/server#更换证书)。
  - 用安全组、防火墙或 VPN 把主 TLS 端口和端口转发的监听端口限制为必要来源（操作者和已放行的目标主机）。
  - `SIREN_MCP_ADMIN_TOKEN` 使用高强度随机值，保存在权限为 `600` 的 `.env` 或服务环境中。
  - 只把 WebUI 账号发给可信操作员；人员变动时删除账号并重启服务端。
  - 不要在 Dossier 目录中放置其他文件，也不要在 Blank template 中粘贴敏感截图。
</Callout>
