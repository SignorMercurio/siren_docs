Agentic IR（AIR）会话运行在服务端上：`siren_server` 以自身系统用户启动 Provider CLI。响应人员使用 **Agentic IR** 页面前，运维人员需先完成本页准备；会话用法见 [Agentic 应急响应](/air)。

## 前置条件

- 服务端运行在 Linux 上。Windows 上运行的服务端，AIR 的 GUI 和 Terminal 都不可用。
- 已启用 MCP、配置 `SIREN_MCP_ADMIN_TOKEN` 并设置 `webui.publicURL`，见 [前置条件与凭证](/server/prerequisites)。`webui.publicURL` 缺失或无效时，Provider 状态仍可能显示可用，但任何会话都会启动失败，报 `webui.publicURL is required for AIR MCP` 或 `webui.publicURL must ...`。

## 支持的 Provider

| Provider | 配置名 | 默认 `cliPath` | 认证 | 历史会话目录 |
| --- | --- | --- | --- | --- |
| Codex | `codex` | `codex` | Codex CLI 自身登录 | `$CODEX_HOME/sessions`，未设置时为 `~/.codex/sessions` |
| Claude Code | `claude` | `claude` | Claude Code 自身登录 | `~/.claude/projects` |
| Qoder | `qoder` | `qodercli` | QoderCLI 自身登录 | `~/.qoder/projects` |
| Pi | `pi` | `pi` | `<agentDir>/auth.json` 中的 Qwen Aegis 密钥 | `<agentDir>/sessions` |

`~` 指 `siren_server` 进程用户的主目录。

## 操作步骤

<Steps>
<Step>

### 安装 CLI 并以服务端用户登录

在服务端安装 CLI，并以运行 `siren_server` 的系统用户登录或认证；登录状态、模型、权限、沙箱和已有 MCP 都从该用户的主目录读取。

`cliPath` 写命令名时，必须能在 `siren_server` 进程的 `PATH` 中找到，否则改为绝对路径。使用 Pi 时另按下文 [Pi](#pi) 准备。

</Step>
<Step>

### 写入服务端配置

在 `server_config.yaml` 的 `air` 段只写与默认值不同的项：

```yaml title="server_config.yaml"
air:
  provider: codex
  maxSessions: 20
  replayBufferBytes: 4194304
  providers:
    claude:
      cliPath: claude
      args: []
    codex:
      cliPath: /usr/local/bin/codex
      args: [--no-alt-screen]
    qoder:
      cliPath: qodercli
      args: []
    pi:
      cliPath: pi
      args: []
      agentDir: /root/.pi/agent
      contextModeDir: /root/.pi/context-mode
      memoryDir: /root/.pi/agent/memory
```

配置只在启动时读取，修改后需重启 `siren_server`。

</Step>
<Step>

### 确认状态

重启后按 [检查可用性](#检查可用性) 查看各 Provider 状态，再用目标 Provider 启动一次 Manual 会话，验证登录状态和 MCP 注入。

</Step>
</Steps>

## Pi

Pi 复用服务端用户的全局 Pi 安装、插件、Skills、配置和 memory，新会话固定从 Qwen Aegis 模型开始。安装脚本和默认目录都按 root 设计。

1. 在 SIREN 源码仓库中以 root 运行安装脚本（需要 Node.js 24）。脚本全局安装 Pi CLI 及其插件，并把 SIREN 的 Pi 配置合并进 Agent 目录：

   ```bash title="SIREN 源码仓库（root）"
   QWEN_AEGIS_API_KEY=<Qwen Aegis API Key> bash scripts/install_pi_provider.sh
   ```

   Agent 目录默认 `/root/.pi/agent`，可用 `SIREN_PI_AGENT_DIR` 指定。设置了 `QWEN_AEGIS_API_KEY` 时脚本写入 `auth.json`，否则只提示 Qwen Aegis 暂不可用。

2. 确认 `<agentDir>/auth.json` 权限为 `0600`，且含 `type` 为 `api_key`、`key` 非空的 `qwen-aegis` 条目，否则 Pi 的 GUI 和 Terminal 都不可用：

   ```json title="/root/.pi/agent/auth.json"
   {
     "qwen-aegis": { "type": "api_key", "key": "<Qwen Aegis API Key>" }
   }
   ```

3. 不要在 `<agentDir>/mcp.json` 中手工添加名为 `siren` 的 MCP Server，它会与 SIREN 为每个会话动态注册的 MCP 冲突。

<Callout title="不要只改 agentDir" type="warn">
  安装脚本写入的 `models.json` 固定从 `/root/.pi/agent/auth.json` 读取密钥，而 SIREN 检查的是 `air.providers.pi.agentDir` 下的 `auth.json`。改了 Agent 目录却不同步 `models.json` 的读取路径，状态检查会通过，实际请求仍认证失败。
</Callout>

Pi 的文件、Shell、MCP 和子 Agent 操作直接执行，不产生权限审批。

## 检查可用性

| 界面 | 可用条件 |
| --- | --- |
| Terminal | 服务端不是 Windows；`cliPath` 可执行；Pi 还要求 `auth.json` 通过检查 |
| GUI | 满足 Terminal 条件，且与 CLI 的协议握手成功 |

升级或安装 CLI 后重新检查即可，不需要重启 SIREN。

<Callout title="状态不代表已登录" type="warn">
  Claude Code、Codex 和 Qoder 的检查不验证登录状态。CLI 未登录时，会话启动后由 CLI 自己报错。
</Callout>

**Settings** 页 **Server** 区的 **AIR runtime** 显示 AIR 不可用的原因，并列出各 Provider 可用的界面和不可用原因；每次打开 Settings 都会重新检查。**Agentic IR** 页中也可点击 **Running** 旁的刷新按钮重新检查。

| 显示内容 | 处理 |
| --- | --- |
| `Codex CLI was not found`（其他 Provider 同理） | 安装 CLI，或把 `cliPath` 改为绝对路径后重启 |
| `structured AIR is not supported on Windows servers` | 改用 Linux 服务端 |
| `Pi Qwen Aegis authentication is missing: ...` | 按上文写入 `auth.json` |
| `Pi authentication file ... has mode ...; expected 0600` | `chmod 600 /root/.pi/agent/auth.json` |
| `Pi qwen-aegis model is not configured or authenticated` | 重新运行 Pi 安装脚本，确认 `models.json` 中有 `qwen-aegis` |
| `Qoder ACP protocol version ... is incompatible; SIREN requires v1` | 升级 QoderCLI |
| `Claude CLI does not advertise bidirectional stream-json` 或握手请求失败 | 升级对应 CLI；升级前可先用 Terminal |

## 配置项

各键的类型和默认值见 [配置文件](/reference/server-config#air)。以下是需要额外说明的行为：

- **`air.provider`**：回退 Provider。浏览器默认选用上次使用的 Provider（首次为 Codex），可在 **Settings** 的 **Default AIR provider** 中固定；所选 Provider 不可用时先回退到 `air.provider`，再回退到第一个可用的 Provider。
- **`air.maxSessions`**（默认 `20`）：全服务端 AIR 会话上限，GUI 与 Terminal、所有 Project、Manual/Custom/Event 和继续会话合计；超出时报 `agent session limit reached (N)`。`0` 或负数表示不限制。
- **`air.replayBufferBytes`**（默认 4 MiB）：每个会话的断线重连回放预算，Terminal 按原始输出、GUI 按结构化事件计算。`0` 或负数时使用默认值，不会关闭回放。

### Provider 参数

- **Codex**：默认的 `--no-alt-screen` 让 Terminal 保留浏览器终端的滚动历史；旧版 Codex 不识别该参数时设为 `args: []`。SIREN 注入的 `siren` MCP Server 会覆盖用户配置中的同名条目。
- **Claude Code、Qoder**：SIREN MCP 配置、会话 ID 和 GUI 传输参数由 SIREN 加入，不要写进 `args`。
- **Pi**：`args` 中的 `--session`、`--resume`、`--session-id`、`--provider`、`--model`、`--thinking`、`--mode` 会被丢弃，由 SIREN 决定。

模型、推理强度、权限、沙箱、Shell 审批和工具限制写进对应 CLI 的用户配置或 `args`，SIREN 不配置。

### Prompt 模板

Custom 和 Event 入口用模板生成种子 prompt，默认值见 [配置文件](/reference/server-config#air)：

| 配置项 | 用于 | 占位符 |
| --- | --- | --- |
| `air.prompt` | Event：安全中心告警 ID | UID、告警 ID、Client ID |
| `air.instancePrompt` | Event：ECS 实例 ID | UID、实例 ID、Client ID |
| `air.assetPrompt` | Event：云安全中心资产 UUID | UID、资产 UUID、Client ID |
| `air.timeRangePrompt` | 实例或资产目标限定时间范围时追加 | 时间范围 |
| `air.customPromptPrefix` | Custom：加在用户 prompt 之前 | Client ID |

占位符按表中顺序填入，`%s` 为文本、`%d` 为数字，修改时须保持数量和顺序。时间范围形如 `最近 7 天`、`2026-10-01 08:00 至 2026-10-02 08:00` 或 `2026-10-01 08:00 至今`。

## 边界

<Callout title="SIREN 只做这些" type="info">
  - 用 `cliPath` 和 `args` 启动 CLI，为所有入口（包括 Manual）注入当前范围的 SIREN MCP 和会话凭证，并按入口加入种子 prompt 或要继续的会话 ID。
  - GUI 只展示 Provider 主动返回的审批和提问；“本会话允许”不写入 CLI 的用户级配置。
  - 不修改 Claude Code、Codex、Qoder 的全局设置，也不替它们跳过权限确认。
  - 会话凭证随会话结束或服务端重启失效；长期 MCP 管理凭证不会注入 Provider。
</Callout>

## 常见问题

<Accordions>

<Accordion title="Settings 显示可用，但会话一启动就失败">

- `webui.publicURL is required for AIR MCP`：未设置 `webui.publicURL`，见 [前置条件与凭证](/server/prerequisites)。
- `agent session limit reached (N)`：已达 `air.maxSessions`，先在 **Running** 中停止不用的会话。
- CLI 自身的登录或认证错误：用 `siren_server` 的系统用户重新登录该 CLI。

</Accordion>

<Accordion title='Pi 报 MCP server "siren" is already registered'>

删除 `<agentDir>/mcp.json`（默认 `/root/.pi/agent/mcp.json`）中名为 `siren` 的静态条目，SIREN 会为每个会话动态注册。

</Accordion>

<Accordion title="GUI 不可用，但 Terminal 可用">

CLI 版本过旧或协议握手失败。可先用 Terminal；升级 CLI 后重新检查即可，不需要重启 SIREN。

</Accordion>

</Accordions>
