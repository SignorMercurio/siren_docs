只有 TLS 证书、MCP 凭证（默认启用 MCP 时）和 `egress.rules`（启用 WebUI 时）会阻止服务端启动；其他依赖缺失只影响对应功能。

## 总览

| 依赖 | 需要它的功能 | 缺失时 |
| --- | --- | --- |
| [TLS 证书和私钥](#tls-证书和私钥) | 所有连接 | 服务端无法启动 |
| [WebUI 用户库](#webui-用户库) | Web 控制台登录 | Web 控制台不鉴权，任何人可匿名操作 |
| [MCP 凭证](#mcp-凭证) | MCP、Agentic IR | 启用 MCP 时服务端拒绝启动 |
| [出站规则 `egress.rules`](#出站规则-egressrules) | **Configure egress**、客户端部署 | 启用 WebUI 时服务端拒绝启动；未启用 WebUI 时部署失败 |

## 设置服务端环境变量

MCP 和 SOAR 凭证都从环境变量读取，不要写进 `server_config.yaml`、Project 目录或 Git 仓库：

- **`.env` 文件（推荐）**：启动时依次读取当前工作目录和二进制所在目录下的 `.env`，环境中已有的同名变量优先。建议权限 `600`。
- **Shell 导出**：在启动 `siren_server` 的 tmux 窗口里 `export`。
- **REPL `env KEY=VALUE`**：只修改当前进程，重启后失效。

```bash title="/opt/siren/.env"
SIREN_MCP_ADMIN_TOKEN=<随机字符串>
SOAR_ACCESS_KEY_ID=<AccessKey ID>
SOAR_ACCESS_KEY_SECRET=<AccessKey Secret>
```

<Callout title="AIR 子进程会继承服务端环境" type="warn">
  Agentic IR 启动 Provider CLI 时会剔除 `SIREN_MCP_ADMIN_TOKEN` 等长期 MCP 凭证，但 SOAR、阿里云 AccessKey 等其他变量原样传入，见 [账号与安全边界](/server/security#mcp-鉴权)。
</Callout>

## TLS 证书和私钥

- **配置**：顶层 `cert` / `key`，默认 `certs/cert.pem` / `certs/key.pem`，相对工作目录解析。安装脚本生成的自签证书只覆盖 `localhost` 和 `127.0.0.1`。
- **要求**：浏览器访问的域名和 `webui.publicURL` 中的域名都必须在证书中，且证书受浏览器信任。
- **缺失时**：启动失败，提示 `configure server TLS`。更换方法见 [更换证书](/server#更换证书)。

## WebUI 用户库

- **配置**：`siren_server user add <username>` 创建账号，存入 SQLite 账号库（默认 `data/users.db`，可用 `webui.userDBPath` 改为绝对路径）。
- **缺失时**：启动时账号库不存在或没有账号，本次运行期间 Web 控制台完全不鉴权，创建第一个账号后需要重启，见 [WebUI 账号](/server/security#webui-账号)。

## MCP 凭证

- **配置**：环境变量 `SIREN_MCP_ADMIN_TOKEN`，非空随机字符串，可用 `openssl rand -hex 32` 生成。外部 MCP 客户端凭它访问，见 [MCP 集成](/reference/mcp#端点)；Agentic IR 会话自动获得临时凭证，无需配置。
- **缺失时**：`mcp.enabled: true`（默认）时拒绝启动，提示 `MCP requires SIREN_MCP_ADMIN_TOKEN`。设置 `mcp.enabled: false` 可不再要求该变量，但 Agentic IR 随之不可用。

## 出站规则 `egress.rules`

- **用于**：**Configure egress** 为目标 ECS 下发的出方向放行规则；客户端部署依赖其中的 `siren_server_callback` 规则。
- **配置**：`server_config.yaml` 中 1 到 20 条规则，每条包含：
  - `purpose`：snake_case 标识，不能重复
  - `ipProtocol`：`TCP`、`UDP`、`ICMP`、`GRE` 或 `ALL`
  - `destCidrIp`：IPv4 CIDR，主机位必须为 0
  - `portRange`：如 `443/443`；`ICMP`、`GRE`、`ALL` 必须为 `-1/-1`
- **缺失时**：启用 WebUI 时，规则缺失或任一条无效都会拒绝启动，没有内置默认规则；未启用 WebUI 时可以启动，但部署会失败。

`siren_server_callback` 必须是单端口 TCP 规则，`destCidrIp` 填本服务端供客户端连接的公网 IP（`/32`），`portRange` 填客户端连接端口：

```yaml title="server_config.yaml"
egress:
  rules:
    - purpose: siren_server_callback
      ipProtocol: TCP
      destCidrIp: 203.0.113.10/32
      portRange: 443/443
```

安装包自带的 `47.111.170.208` 是官方服务端，自建服务端必须改成自己的公网 IP。这条规则同时决定部署时放行的服务端端口、出口发现的探测目标（不一致时提示 `probe destination differs from configured SIREN callback; no IP was allowed`）和一键部署写入客户端 `config.yaml` 的连接地址。另两条默认规则 `siren_client_download`、`alibaba_cloud_infrastructure` 用于下载客户端和访问阿里云基础服务。下发和恢复见 [出站放行](/onboard/egress)。

## 出口发现 `egress.discovery`

部署（**Deploy SIREN**、REPL `deploy` / `deploy-batch`、MCP `deploy`）时未手动填写出口 IP，SIREN 让目标主机发出一次探测连接，再通过 SOAR 查询云防火墙日志找出它的来源 IP，只放行这个 IP。

```yaml title="server_config.yaml"
egress:
  discovery:
    uid: "1234567890123456"                 # 云防火墙所在账号 UID
    region: cn-hangzhou                     # 日志服务地域
    project: <云防火墙日志 Project>
    logstore: cloudfirewall-logstore
```

- **要求**：服务端入方向流量经过阿里云云防火墙且日志投递到上述 Logstore；SOAR 凭证可执行 `sls_query` 剧本查询该 Logstore。
- **缺失时**：未配置的字段使用指向内部环境的内置默认值。查询失败、120 秒内未查到日志、匹配到多个来源或探测失败时，部署停止并提示手动指定出口 IP。

## SOAR 凭证

- **用于**：上表所列操作（含对应的 REPL `allow`、`deploy`、`deploy-batch` 和 MCP `deploy`）。
- **配置**：环境变量 `SOAR_ACCESS_KEY_ID` / `SOAR_ACCESS_KEY_SECRET`，必须成对设置，只设一个会报错。都未设置时回退到 Alibaba Cloud SDK 默认凭证链，例如 `ALIBABA_CLOUD_ACCESS_KEY_ID` / `ALIBABA_CLOUD_ACCESS_KEY_SECRET`。
- **缺失时**：服务端照常启动，上述操作执行时报错。

凭证在首次使用后缓存，之后改 `.env` 或 Shell 环境需要重启服务端。在 REPL 中用 `env` 设置上述任一变量会立即生效，但只作用于当前进程：

```bash title="SIREN Server"
>>> env SOAR_ACCESS_KEY_ID=<AccessKey ID>
>>> env SOAR_ACCESS_KEY_SECRET=<AccessKey Secret>
```

## webui.publicURL

- **配置**：证书覆盖的 HTTPS Origin，并在控制主机本机把该域名解析到本机的非回环内网地址，见 [安装服务端](/server#webuipublicurl)。
- **缺失时**：服务端照常启动；启动 Agentic IR 会话时提示 `webui.publicURL is required for AIR MCP`。

## Dossier 目录

- **配置**：`webui.dossierDir`，安装包配置为 `/opt/siren/dossier`。需要单独部署 Dossier 静态文件，见 [部署 Dossier](/server/dossier)。
- **缺失时**：Reports 仍列出报告，但无法在 Dossier 中打开；Settings 的 **Dossier** 一栏显示原因。

该目录通过 `/dossier/` 不鉴权对外提供，不要存放其他文件，见 [`/dossier/` 不鉴权](/server/security#dossier-不鉴权)。

## AIR Provider CLI

在控制主机上安装并登录 Codex、Claude Code、Qoder 或 Pi CLI，由 `air.providers.<name>` 指定路径和参数，见 [准备 AIR Provider](/server/air-providers)。缺失时 Settings 的 **AIR runtime** 下显示对应 Provider 不可用及原因。

## tmux

服务端需要常驻终端，在 tmux 中运行，见 [保持服务端运行](/server#保持服务端运行)。REPL 的 `shell` 命令没有 tmux 时无法使用；WebUI 的 Shells 和 Agentic IR 不依赖 tmux。

## 网络

| 方向 | 需要放通 |
| --- | --- |
| 入方向 | 主 TLS 端口（默认 `443`）对目标主机出口 IP 和操作者开放；使用[端口转发](/reference/portforward)时另开对应端口 |
| 服务端出方向 | `oss-siren.oss-cn-hongkong.aliyuncs.com`（安装、升级和启动时的版本检查）、SOAR 接入点 `sophonsoar.aliyuncs.com`、各 AIR Provider 的模型服务 |
| 目标主机出方向 | 客户端下载地址和服务端连接端口，可用 **Configure egress** 下发 |

## OSS 凭证

只用于本地模式：目标主机上的 `siren recon` 把结果上传到 OSS，`siren upload` 上传指定文件；远程模式不需要 OSS。在运行本地命令的终端中设置（客户端不读取 `.env`）：

```bash tab="Linux"
export HISTCONTROL=ignoreboth
 export OSS_ACCESS_KEY_ID=<YOUR_ACCESS_KEY_ID>
 export OSS_ACCESS_KEY_SECRET=<YOUR_ACCESS_KEY_SECRET>
```

```powershell tab="Windows"
$env:OSS_ACCESS_KEY_ID="<YOUR_ACCESS_KEY_ID>"
$env:OSS_ACCESS_KEY_SECRET="<YOUR_ACCESS_KEY_SECRET>"
```

Linux 中凭证命令前的空格配合 `HISTCONTROL=ignoreboth` 可避免写入 Bash 历史。

Bucket 和上传路径由客户端配置 `oss.region`、`oss.bucketName`、`oss.objectPath`、`oss.docObjectPath` 指定，见 [配置文件](/reference/client-config)。凭证缺失或无权限时，采集结果仍保存在本机，但 `siren recon` 以上传错误结束。

## 插件市场

客户端配置 `plugins.marketplace` 指定插件市场的 HTTP(S) 地址（例如 OSS Bucket 地址），只在安装或更新[插件](/reference/plugins)时需要。
