Dossier 是纯静态的报告编辑器，不随 `siren_server` 打包。SIREN 从 `webui.dossierDir` 读取 Dossier 运行时并在 `/dossier/` 下提供，WebUI 中所有在 Dossier 中打开报告的入口都依赖它。编辑器用法见 [报告工作流](/reports)和 [语法](/reports/syntax)。

## 前置条件

- 已 [安装 SIREN 服务端](/server)，且 `webui.enabled` 为 `true`。
- 构建机上有 Dossier 源码仓库和 Node.js 22 或更新版本，并已执行 `npm ci`。
- 使用 `make deploy` 时，构建机还需要 `rsync`，并能通过 ssh 登录 SIREN 服务端。

## 运行时文件

| 文件 | 作用 |
| --- | --- |
| `index.html` | 编辑器入口，缺失时视为未部署 |
| `editor.js`、`editor.css` | 构建产物 |
| `report.md` | 默认报告模板，**Blank template** 打开的就是它 |
| `assets/` | 字体和图片等本地资源 |

## 使用 make deploy 发布

从构建机远程发布，失败时自动回滚。

<Steps>
<Step>

### 预演

```bash title="Dossier 仓库"
npm ci
make deploy-dry-run
```

预演只列出将要同步的变化，不修改服务端。

</Step>
<Step>

### 发布

```bash title="Dossier 仓库"
make deploy
```

`make deploy` 把运行时发布到 `DOSSIER_DEPLOY_DIR`（默认 `SIREN:/opt/siren/dossier`，`SIREN` 是 ssh 主机名），并把 `report.md` 同步到 Sleuth skill 的模板目录 `SKILL_DIR`（默认 `../sleuth/skills/sleuth/assets`）。`SKILL_DIR` 不存在或不可写时，部署在动服务端之前中止。只需要其中一部分时：

```bash title="Dossier 仓库"
make deploy-runtime                       # 只发布 SIREN 上的运行时
make deploy-runtime-dry-run               # 预演运行时发布
make deploy-skill                         # 只同步 Sleuth 模板
DOSSIER_DEPLOY_DIR=siren-prod:/opt/siren/dossier make deploy-runtime
```

</Step>
<Step>

### 配置 SIREN

首次部署或更换目录时，按 [配置 SIREN](#配置-siren) 设置 `webui.dossierDir` 并重启服务端。之后发布到同一目录不需要重启，刷新编辑器页面即可。

</Step>
</Steps>

`DOSSIER_DEPLOY_DIR` 必须是 `host:/path` 形式的远程目标，最后一级目录名为 `dossier`；本地路径会被拒绝，同机部署请用 [手工复制](#手工复制)。目标必须是真实目录而非符号链接，且为空或是此前由 `make deploy` 发布过的目录（含 `.dossier-runtime` 标记文件）。发布会保留线上的 `assets/pasted/`。

## 手工复制

不使用 `make deploy`，或构建机就是 SIREN 服务端时：

```bash title="Dossier 仓库"
npm ci
npm run build

sudo mkdir -p /opt/siren/dossier
sudo rsync -av --exclude '.DS_Store' index.html editor.css editor.js report.md /opt/siren/dossier/
sudo rsync -av --delete --exclude '.DS_Store' --exclude 'assets/pasted/' --exclude 'assets/examples/' assets /opt/siren/dossier/
```

手工复制的目录没有 `.dossier-runtime` 标记，之后改用 `make deploy` 发布到这里会被拒绝。需要切换时先创建该标记：

```bash
printf 'Dossier runtime\n' | sudo tee /opt/siren/dossier/.dossier-runtime >/dev/null
```

## 配置 SIREN

```yaml title="server_config.yaml"
webui:
  dossierDir: /opt/siren/dossier
```

也可以用 `siren_server --webui-dossier-dir /opt/siren/dossier` 覆盖。该项没有内置默认值，留空表示不提供 Dossier；随服务端发布的 `server_config.yaml` 已写为 `/opt/siren/dossier`。目录可以位于服务端工作目录之外。

以下情况需要重启 `siren_server`：

- 修改了 `webui.dossierDir`；
- 服务端启动时该目录下还没有 `index.html`。此时 `/dossier/` 会一直返回 “Dossier runtime is not deployed at ...” 直到重启，即使 **Settings** 已显示可用。

`dossierDir` 本身可以是符号链接，但 `make deploy` 的目标不能是。目录内部的符号链接和以 `.` 开头的路径不对外提供。`report.md` 必须是普通文件，解析符号链接后仍须位于该目录内。

## 验证

1. 刷新 WebUI 页面。Dossier 状态在登录后只检查一次。
2. **Settings** 页 **Server** 区的 **Dossier** 行应显示目录路径，不可用时显示原因：

   | 显示内容 | 含义 |
   | --- | --- |
   | `Dossier runtime is not configured` | `webui.dossierDir` 为空 |
   | `Dossier runtime is not deployed at ...` | 目录中没有 `index.html`，或它不是普通文件 |

3. **Reports** 页的 **Blank template** 应能打开模板。只缺 `report.md` 时它不可点击，原因为 `Dossier default report is not deployed at ...`。

## 注意事项

- `/dossier/` 下的静态文件无需登录即可访问，读写报告仍需 WebUI 登录，见 [`/dossier/` 不鉴权](/server/security#dossier-不鉴权)。
- **Blank template** 只读、不能保存。在其中粘贴的图片写入 `<dossierDir>/report.assets/pasted/`，不属于任何报告，下次 `make deploy` 时会被删除。正式报告请从 **Reports** 或 **Artifacts** 打开再编辑。
- 在 SIREN 前面放代理时，按 [单一 TLS 端口](/server#单一-tls-端口) 只做四层透传，并转发整个端口。编辑器通过同源的 `/api/reports/*` 读写报告，只代理 `/dossier/` 会出现页面能打开、但读取或保存失败。

## 本地离线使用

Dossier 也可以脱离 SIREN 使用。在包含运行时文件的目录中启动本地 HTTP 服务，然后访问 `http://localhost:8000`：

```bash
python3 -m http.server --bind 127.0.0.1 8000
```

页面默认加载同目录的 `report.md`；打开其他报告用 `http://localhost:8000/?md=case.md`。报告文件应放在根目录而不是子目录，否则粘贴图片的相对路径会解析错误。

交给其他报告作者时，在 Dossier 仓库中打包：

```bash title="Dossier 仓库"
make dist
```

生成的 `dist/dossier-local-<时间戳>.zip` 包含运行时文件、使用说明和双击启动脚本 `start-mac.command`、`start-windows.bat`。端口被占用时可设置 `PORT` 环境变量。
