自动化信息收集（Recon）会在目标主机上收集系统、用户、进程、网络、计划任务、文件和应用配置等信息，并生成 Markdown 报告。Recon Profile 是“命名的确定性采集集合”：Profile 只选择模块，不覆盖规则、超时或检测逻辑。Recon 只做客观采集并用白名单降低正常环境噪音；是否可疑交给 [Agentic 应急响应](/air) 结合上下文判断，Recon 本身不做挖矿程序、Webshell、Rootkit 等黑名单或签名判定。

<Callout title="前置条件" type="info">
  目标主机需要具备足够权限运行 Recon：Linux 通常需要 root，Windows 需要管理员权限。本地模式会把报告上传到 OSS，需要先[设置 OSS 访问凭证](/credential#设置-oss-访问凭证)；WebUI 和服务端 REPL 不需要 OSS，报告会保存到 SIREN Server 的 Artifacts。
</Callout>

## 使用方式

```text tab="WebUI"
Investigations -> Recon -> 选择客户端和 Profile -> Start Recon
```

```bash tab="服务端 REPL"
>>> recon <Client ID> [Profile]
```

```bash tab="本地模式"
./siren recon [--profile quick]
```

## WebUI 流程

1. 打开 [Web 控制台](/webui#investigations)，进入 **Investigations** 页面。
2. 在 **Recon** 表单中选择在线客户端和该客户端实际提供的 Profile。旧客户端只显示 **Legacy default**。
3. 点击 **Start Recon**，等待客户端回传阶段进度。
4. 报告生成后，点击 **Open Report** 打开对应 Markdown 报告；如果报告尚未生成，也可以点击 **Open Artifacts** 进入当前 Artifacts 目录。

WebUI 会展示本次 operation 的真实 Profile 与采集阶段，比如 `Recon.Basic`、`Recon.User`、`Recon.Process`、`Save report to Artifacts`。同一客户端同时只能运行一个 Recon，不同客户端可并行；冲突、断连、客户端错误和超时都会直接结束当前状态。Project 视图下只能选择当前 Project 的客户端，报告也会写入该 Project 的 Artifacts 目录。

## 查看数据

| 使用方式 | 报告保存位置 |
| --- | --- |
| WebUI | 保存到服务端 Artifacts；已归属 Project 的客户端写入 Project 目录，未归属客户端写入 Global Artifacts |
| 服务端 REPL | 与 WebUI 一样保存到服务端 Artifacts，目录由客户端的 Project 归属决定 |
| 本地模式 | 在当前目录生成 Markdown 文件，并上传到 OSS 的 `<oss.docObjectPath>/<file name>` |

Recon 报告会保留客户端生成的文件名，通常形如 `SIREN_<host>_<timestamp>.md`。服务端保存报告时只接受 Markdown 文件名，并以较严格的文件权限写入。

## 执行规则

- 基础信息每次都会采集，不进入 Profile 模块列表。
- `default` 包含当前平台全部内置模块；`quick` 只移除耗时较长的 `file`，其他模块与 `default` 相同。
- Profile 列表只表达集合；内置模块始终按固定顺序执行，插件按名称排序，保证报告稳定。
- recon 类型插件必须以 `plugin:<name>` 显式写入 Profile，并由 `plugins.<name>` 控制启停。安装插件不会自动修改 Profile；Profile 引用缺失或禁用插件时，采集会在开始前失败，不生成部分报告。
- `chkrootkit` 仍是可选 recon 插件，但不进入 `default` 或 `quick`。插件输出不代表 Recon 核心具备检测能力。
- 每条底层命令的默认超时时间为 30 秒，可通过[客户端配置](/config#客户端配置)中的 `recon.commandTimeout` 修改。

## 信息收集模块

下表列出内置模块 ID。模块是否执行以目标客户端实际加载的 Profile 为准。

<Accordions>
  <Accordion title="Linux 平台模块">

| 模块 | Profile 模块 ID | 采集内容 |
| --- | --- | --- |
| 基础信息 | 始终采集 | 当前时间、OS 发行版、主机名、当前用户、IP 地址、CPU 核数、CPU/内存/磁盘使用率、磁盘挂载（/etc/fstab） |
| 用户 | `user` | 非默认用户、可登录用户、Root 权限用户、sudoers 用户、最近登录记录、`w`/`lastlog` 输出、登录 IP、新增用户记录、`/etc/passwd` 属性 |
| SSH | `ssh` | SSH 暴力破解记录、`~/.ssh/config` 后门、`authorized_keys`、PAM/inetd/软链接后门、`sshd_config` 与 `sshd` 二进制属性 |
| 进程 | `process` | CPU/内存占用 Top 20、systemd 启动进程、其他非默认进程 |
| 网络 | `network` | 监听端口、全 0 开放端口、已建立 TCP 连接、`/etc/hosts`、DNS 服务器、路由表、iptables 规则 |
| 计划任务 | `cron` | 用户级与系统级 cron 任务、cron 日志 |
| 服务 | `service` | 运行中服务、非默认服务文件、`/etc/rc.local`、init.d/rc.d 启动项 |
| 环境变量 | `env` | 环境变量、`LD_PRELOAD`/`LD_LIBRARY_PATH` 等敏感变量、进程环境与 `/etc/ld.so.preload`、profile/rc/environment、`profile.d` 非默认脚本、alias |
| 文件 | `file` | 历史命令、临时目录、SUID 文件、被进程锁定文件、近 1 天变更文件（mtime/ctime）、大文件（>200M）、coreutils 完整性、关键二进制属性 |
| 内核模块（名称保留为 rootkit） | `rootkit` | 白名单降噪后的已加载内核模块（`lsmod`）；不做 Rootkit 检测或 symbol 匹配 |
| 应用 | `application` | Redis 配置、JDWP 调试进程、容器列表 |

  </Accordion>
  <Accordion title="Windows 平台模块">

| 模块 | Profile 模块 ID | 采集内容 |
| --- | --- | --- |
| 基础信息 | 始终采集 | 当前时间、OS 版本、主机名、当前用户、IP 地址、CPU 核数、CPU/内存/磁盘使用率 |
| 用户 | `user` | 非默认用户、可登录用户、管理员组成员、服务账户、禁用/隐藏账户、远程桌面用户、最近登录记录、当前登录用户、新增用户记录 |
| 进程 | `process` | CPU/内存占用 Top 20、进程列表、无文件进程 |
| 网络 | `network` | 监听 TCP 端口、已建立 TCP 连接、hosts 文件、DNS 服务器、网络共享（SMB） |
| 计划任务 | `schtask` | 计划任务、启动文件夹、系统启动项、注册表启动项（Run/RunOnce）、服务启动项 |
| 环境变量 | `env` | 环境变量、PATH、PowerShell 配置文件、Windows Defender 排除项 |
| 文件 | `file` | PowerShell 历史、临时目录、最近访问文件、近 30 天变更的系统目录可执行文件、近 1 天变更的系统日志、启动目录文件、卷影副本 |
| 应用 | `application` | JDWP 调试进程、远程桌面配置、IIS 配置、近 3 天 IIS 日志、Windows Defender 状态 |

  </Accordion>
</Accordions>
