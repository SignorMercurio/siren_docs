## v2.27.0 <DateTag>2026-09-02</DateTag>

### Feature

- Agentic IR 的 GUI 与 Terminal 输入框支持直接粘贴图片（PNG、JPEG、WebP、GIF，单张最多 8 MiB，一次最多 4 张），由 SIREN 转交给 Provider；Claude 与 Codex 支持图片，Qoder 以其 CLI 上报的能力为准，Pi 当前使用的模型不接受图片

### Improvement

- Agentic IR 启动面板：Provider 图标与 GUI/Terminal 开关悬停时显示名称或不可用原因；Manual / Custom / Event 下方显示一行模式说明；输入框、文本框和下拉框统一高度、圆角、悬停与聚焦样式
- Agentic IR 侧栏每次加载默认展开，从 Clients 行内进入时也会自动展开；History 默认收起在侧栏底部，点击标题展开；收起侧栏的箭头固定在分隔线上，窄屏布局同样可用
- Investigations 的 AccessKey、Recon 和 Process Analysis 面板顶部各增加一行用途说明
- Clients 页面没有在线客户端时显示三步引导：部署客户端、等待连接、从客户端行开始排查

## v2.25.0 <DateTag>2026-08-27</DateTag>

### Feature

- Linux 与 Windows 的 `hunt` Profile 默认加入跨平台 `supplychain` 模块，记录当前运行应用、中间件、真实监听程序和运行中容器载荷对应的可执行文件摘要、版本来源、依赖清单及容器镜像引用；不再生成全系统软件包清单或散列全部主机进程

### Improvement

- 运行载荷可执行文件使用流式 SHA-256，并同时执行 128 文件、64 MiB 单文件和 512 MiB 总读取边界；读取失败、采集期间变化、文件过大或总预算耗尽会以独立 coverage 原因呈现，不输出可能不一致的摘要
- `supplychain`、`config` 与 `credential` 复用同一路径的 canonical evidence，后续模块仍可补充内容、关系和凭据分类；完整文件摘要另受 8 MiB 单文件与 64 MiB Snapshot 总读取边界约束
- Hunt Markdown 使用实际 selected、processed、collected、failed 和 reused 数量汇总供应链覆盖；运行态 producer 的部分结果、失败和容器 runtime 未安装会保留各自语义，不再被空结果掩盖

### Bugfix

- 修复 Linux 大小写不同的证据路径被错误合并、preview 先发现后无法升级为直接引用内容，以及首次内容定位写入受模块上限拒绝后无法由后续模块补写的问题
- 修复已停止容器、命名 volume 和无关语言运行时进入运行载荷证据，以及带空格的依赖参数和 digest-only 镜像引用解析不准确的问题
- 修复配置 include/reference 闭包、JAR 元数据和证据文件读取缺少完整硬边界或稳定文件校验，可能造成漏项、越界读取或不一致摘要的问题

- Hunt Markdown 改为按应用、容器、真实监听和容器端口分类稳定限额，瞬时连接只汇总数量与地址范围，partial 来源按模块和原因聚合

### Bugfix

- 修复 request dump、分析报告和候选结果等应用运行输出被当作完整配置采集，导致快照因单文件 256 KiB 上限长期显示 partial 的问题

## v2.23.2 <DateTag>2026-08-21</DateTag>

### Feature

- Hunt 默认加入 opt-in `activity` 模块，在不引入持续 Recorder 的前提下采集当前运行应用与容器直接关联的近期本地日志尾部；候选限定最近 24 小时、最多 16 个文件、每文件 256 KiB、总计 4 MiB，正文只保存在权威 JSONL，Markdown 仅显示覆盖摘要

### Improvement

- Recon 为 OS、资源、网络、环境变量、计划任务和安全组件等 Agent 高频事实补充稳定字段，并在 source coverage 中分别统计结构化记录、原始证据和报告结构记录；无法可靠解析的配置、脚本、日志和历史仍完整保留为 raw evidence，不会因此误报 partial
- Windows Hunt 增加类型化路由与计划任务证据，旧版系统可通过 WMI 和 Task Scheduler COM 回退获取任务状态、运行用户、动作和触发器
- Hunt 使用同一瞬时快照中的稳定实体 ID 串联父子进程，并让每条已建立连接引用实际 Socket、本地地址、远端地址、协议和状态；同一进程到同一远端的多个 Socket 分别保留

### Bugfix

- 修复 Process 等运行态实体同时被所属模块和 Topology 重复写入，导致 Hunt Snapshot 与 Markdown 实体数量翻倍的问题；新快照按实体归属只写一条，历史重复快照也按稳定 ID 去重汇总
- 修复应用拓扑把 systemd unit 或 Windows Service 当作主要应用服务的问题；主拓扑现在聚焦 Web 服务、中间件、应用运行时、容器和对外监听进程，系统服务只保留为辅助启动关系

## v2.21.1 <DateTag>2026-08-19</DateTag>

### Feature

- Recon 新增 Snapshot JSONL v1：`*.recon.jsonl` 作为权威主机快照，服务端校验后确定性生成同名 Markdown，并在本地、Global Artifacts 和 Project Artifacts 中保留双 artifact
- Recon wire protocol 升级到 v2，公布 artifact format，并在结果中返回 Profile、`complete|partial` 状态和 snapshot 文件名；v1 Markdown 与 Legacy default 客户端继续兼容

### Improvement

- Recon 改为有明确范围与上限的客观采集：source、module、字段和整份快照均有硬限制，工具缺失、采集失败与截断会记录为 `unavailable`、`failed` 或 `partial`
- 删除客户端 `rules` 与白名单过滤，账户、进程、任务、服务、内核模块、环境变量、配置和历史记录按声明范围原样采集，分析与判断交给 AIR
- Linux Recon 不再自动安装 `netstat` 或 `lsof`，改用原生能力、已有工具回退和明确的 unavailable 状态
- Recon 为每个 source 提供独立命令预算；Linux 文件视图按底层文件系统去重并由单次遍历生成，Windows 大目录与进程、socket、任务、服务查询按稳定字段排序后应用结果上限
- Recon 新增默认 270 秒的 Profile 总采集预算；远程 v2 请求会提前收敛客户端采集并支持按 request ID 取消，服务端超时后立即释放单飞占用
- v2 Snapshot 在客户端和服务端之间流式传输，服务端在接收正文前执行 128 MiB 上限检查，避免大快照产生多份内存副本
- 服务端会严格校验 Snapshot 的事件顺序、范围和状态后再生成 Markdown，格式无效时立即返回错误
- WebUI 继续只提供 **Open Report**，partial 快照显示简短警告；MCP 正文继续返回 Markdown，并补充 status、report path 与 snapshot path，正文预览上限为 2 MiB
